# M6.5：规则和分类管理

> 目标：存进去的规则能看到、改掉、删掉，分类不用再靠 seed 或手写 SQL 加；重跑 seed 不会把管理页里的改动冲掉。
> 参考：`docs/prd.md` F5；`docs/business-rules.md` R7、R7.2、R13、R16.3、R16.5、R16.6、R18、R19；`docs/seed-categories.md`；`docs/design/README.md`（12、13，第 3 节分类 tag 颜色和分类下拉）
> 涉及页面或数据库的任务，先用 plan mode 说打算怎么做，我同意了再写。

## 通用要求

- 这个里程碑不改表结构，不加新依赖（shadcn/ui 的组件不算，用到新的先说一声）
- 规则写成纯函数放 `src/lib/rules/`，数据层放 `src/server/`，写入用 Server Actions + Zod
- 分类匹配复用 `classify.ts`（`matchRule`、系统规则），重新应用复用 `planReapply` / `previewReapply` / `reapplyRules`，不另写一套
- 关键词规范化复用 `normalizeKeyword`（现在在 `src/server/rules.ts`，纯函数可以挪到 `src/lib/rules/`）
- 分类下拉复用 F8 的 `category-picker`（可选范围按 R16.3）；要挪到 `src/components/` 共用就挪，别复制一份
- 分类 tag 颜色用 `category-color.ts`，新建的一级已经支持按 id 挑色
- F8 的"存成规则"弹窗行为不变：撞了关键词仍按 R16.6 问要不要改；只有设置页按 R18.2 直接报错
- "要对 N 笔应用吗"在 N = 0 时和 F8 一样：不弹框，toast 写"没有需要重新分类的交易"
- 侧边栏"设置"下加"规则""分类"两项（`src/components/app-shell/nav.ts`）
- 全部带 `household_id`

## 边界情况

- 新的二级插在 Other 前面，Other 始终最后；新的一级排同组最后（R19.2）
- 和归档的分类重名：报错让用户去取消归档，不自动恢复（R19.2）
- 一级取消归档时所有二级一起恢复，包括之前单独归档的，不改表（R19.4）

## M6.5-2 规则管理规则（纯函数）

- [x] 完成

**规则**：R7、R18.1 到 R18.4
**文件**：新建 `src/lib/rules/rule-admin.ts`；`classify.ts` 可能要导出系统规则的判断

**做什么**

- `ruleHits(txs, rules)`：R18.1 命中数。每笔交易按 R7 第 3 步找出胜出的规则，计到那条规则上；内部转账（`auto`、`confirmed`）和命中系统规则的不算；不管现在的分类和来源
- `checkRuleEdit(input, rules, categories, selfId?)`：R18.2 规范化关键词、检查分类能不能选（R16.3）、`(keyword, match_type)` 撞了返回"已有规则 X → Y"；改的是自己这条不算撞
- `filterRules(rules, { search, topCategoryId }, categories)`：按关键词字母排序；搜索包含、不区分大小写；按一级筛选包括它的二级
- R18.4 不用新函数，用现有的 `planReapply` 把表里三行写成测试

**完成标准**

- 有 `COLES` 和 `COLES EXPRESS` 两条规则：`COLES EXPRESS 1234` 只算到 `COLES EXPRESS`，`COLES 0559 MELBOURNE` 算到 `COLES`
- 商家含关键词但交易是内部转账、或以 `ATM` 开头：不算命中
- 分类是 `manual` 的交易照样算命中
- 关键词 `  blue   cafe ` → `BLUE CAFE`；空的、超过 100 字符报错
- 把 A 规则的关键词改成 B 规则的（同匹配方式）报错，信息写 B 指向的分类；只改 A 的分类不报错；`CAFE` 包含 和 `CAFE` 开头是 能同时存在
- 分类选内部转账、归档的报错
- R18.4 例子三行，"不应用"和"应用"各一个测试，`BLUE CAFE BAR` 结果和表一致；改分类那行归属人按 R5.1 重算
- 已有测试全部还能通过

## M6.5-5 分类管理规则（纯函数）

- [x] 完成

**规则**：R16.3、R19.2 到 R19.4
**文件**：新建 `src/lib/rules/category-admin.ts`

**做什么**

- `normalizeCategoryName(name)`：去首尾空格、多个空格合成一个，最长 50，不能为空
- `checkNewCategory(input, categories)`：一级要选类型；二级跟一级；税前只有收入的二级能勾；不能在二级下建；重名（不区分大小写，同一个一级下 / 一级之间，含归档的）报错，和归档的重名时提示去取消归档
- `newCategorySortOrder(...)`：一级排同类型最后；二级插在 Other 前面，返回新二级的 sort_order 和 Other 要改成的值
- `checkCategoryEdit(category, edit)`：R19.3 能改、不能改的，Other 不能改名，系统分类都不能改
- `planArchive(categoryId, categories, ruleCounts)`：R19.4。返回要归档的 id（一级带上所有二级），或者原因：系统分类、Other 单独归档、有 N 条规则指向
- `planUnarchive(categoryId, categories)`：二级的一级还在归档中时报错；一级恢复时带上所有二级

**完成标准**

- 新建一级 `Kids`（支出）：返回一级和一个 `Other`（`is_other = true`），排在支出最后
- 在 Entertainment & eat-out 下新建 `Gaming`：排在 Other 前面，Other 往后挪
- `  gaming  ` 和已有的 `Gaming` 重名报错；和归档的 `Gaming` 重名时报错信息提示取消归档
- 收入的二级能勾税前；支出的二级、一级勾了报错
- Other 改名报错，改默认归属人可以；系统分类改什么都报错；改类型、改所属一级报错
- 有 1 条规则指向 Coffee & tea 时归档它报错，信息带"1 条规则"；归档 Entertainment & eat-out 也报错（规则指向它的二级）
- 规则删了以后归档 Entertainment & eat-out：返回一级和它所有二级
- 一级归档中时恢复它的二级报错；恢复一级时所有二级一起恢复
- 已有测试全部还能通过
