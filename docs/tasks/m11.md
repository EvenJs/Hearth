## 边界情况

2026-11-03 全部定了，M11-1 写进 R25。

**目标的字段**

| 字段 | 说明 |
| --- | --- |
| 名字 | 必填，同家庭不重名（只算没完成的） |
| 类型 | `keep` 存着的 / `spend` 要花掉的 |
| 重复 | `once` / `yearly`，只有 `spend` 能选 `yearly` |
| 目标金额 | 分，> 0。应急金不填，自动算 |
| 目标日期 | 可选。`yearly` 必填 |
| 挂的账户 | 可选，一个。只能选本家庭、没归档、不是现金的账户（2026-11-03 定） |
| 优先级 | 整数，全家一个顺序（`/goals` 列表的顺序），同一账户里按它填 |
| 应急金 | 布尔 + 月数（默认 6，1 到 24 的整数）。**一个家庭最多一个应急金目标**，类型固定 `keep` |
| 固定到首页 | 布尔，默认不固定 |
| 状态 | `active` / `done`。`done` 记 `done_at` |

- 一个目标只挂一个账户（prd F14 定的，proposal N3 里的"一个或几个"不做）
- 账户后来归档了：目标还在，显示"账户已归档"，没有进度，每月要存照算

**每月要存**

- 还差 = 目标金额 − 已填进度（没挂账户的：还差 = 目标金额，因为没有进度）
- 月数 = 目标日期所在月 − 本月（不含目标月当月），**最少 1**。例子：今天 2026-11-03，目标 2027-03-15 → 11、12、1、2 月 = 4 个月。目标月当月不算（2026-11-03 定）
- 每月要存 = 还差 ÷ 月数，**向上取整到分**（宁可多存 1 分）
- 没有目标日期 → 不算每月要存，不进合计
- 已经达成（还差 ≤ 0）→ 0
- 目标日期已经过了、还没达成 → "已过期，还差 $X"，不算每月要存，不进合计，提示"日期往后推"
- `done` 的目标不算

**优先级填进度**（prd F14）

- 用挂的账户的**可用余额**（R23.2，和 R23.5 合计用的一样）。账户没锚点 → 这个账户上的目标都显示"账户还没有余额"，没有进度
- 同一账户上 `active` 的目标按优先级排，余额先填满第 1 个（填 min(剩下的余额, 目标金额)），剩下的给第 2 个，依次往下
- 余额是 0 或负数 → 全部 0
- 已经达成的 `keep` 目标继续占着钱（钱一直放着）
- `done` 的不参与，所以买完一个，后面的自动往前顶（余额也少了，看结果）
- 应急金的目标金额算不出来（没有完整月，R22.5 n = 0）→ 这个目标不占钱、显示"还没有月均"，后面的照填（2026-11-03 定）
- 例子（prd）：储蓄账户 $7000，1. 包 $5000 → 已存够；2. 旅行 $4000 → 已存 $2000，还差 $2000

**预计达成**

- 只给挂了账户、有余额、还没达成的目标
- 账户月净流入 = 这个账户近 3 个**完整月**全部交易（任何分类、含转账、含 pending）的 `amount_cents` 合计 ÷ 月数。窗口和起点照 R22.5，起点用这个账户最早一笔交易的月份；n = 0 → "数据不够，估不出来"
- 第 k 个目标要等前面 1 到 k 都填满：需要 = Σ(1..k 的目标金额) − 账户可用余额；月数 = ceil(需要 ÷ 月净流入)；预计达成 = 本月 + 月数（显示到月，如"预计 2027-05"）
- 净流入 ≤ 0 → "按现在的速度达不到"
- 有目标日期、预计晚于目标日期 → 标红"比目标晚 N 个月"
- 没挂账户 → 不估，只显示每月要存

**存不存得过来**

- 每月要存合计 = 所有 `active`、有日期、没过期的目标的每月要存相加
- 实际每月存下 = 近 3 个完整月的 (收入 − 支出) 合计 ÷ 月数，口径同 R10（全家，不跟看板筛选）。窗口同 R22.5
- 支出**排除挂了目标的拆分**：那是目标的钱花掉了，不算"没存下"。不排除的话，买包那个月会显示存不过来（2026-11-03 定）
- 合计 > 实际 → `/goals` 顶部提示"目标每月要存 $X，近 3 个月平均只存下 $Y，目标太多，或者日期往后推"
- 实际 ≤ 0 → 一样提示
- 税前收入会让实际偏高（R10 已知局限），提示旁边不另外说明

**应急金**

- 目标金额 = 近 12 个月月均（R22 总月均，全家，已排除一次性）× 月数。月均变了，目标金额跟着变
- 能撑几个月 = 已填进度 ÷ 近 12 个月月均，**向下取整到 0.1**（"能撑 3.4 个月"）
- 月均 ≤ 0 或算不出来 → "—"
- 没挂账户 → 不显示能撑几个月，只显示目标金额
- 不跟看板的归属人筛选
- 不能标 `done`（存着的目标不会结束）

**要花掉的目标：挂交易**

- 挂在**拆分**上（`transaction_split.goal_id`），因为一次性也在拆分上。只有支出口径的拆分能挂（同 R22.1）
- 只能挂 `active` 的 `spend` 目标；一个拆分最多挂一个目标；一个目标可以挂多笔（旅行：机票、酒店）
- 挂上时**自动把 `is_one_off` 设成 `true`**；取消挂不动 `is_one_off`（2026-11-03 定）
- 退款也能挂，冲减实际
- 实际 = −Σ 挂上的拆分金额（支出是负数，翻成正数）。显示"计划 $5000，实际 $5200，多了 $200"
- 交易可以来自任何账户（存在 saver，用信用卡买）
- 挂交易**不自动完成**。挂了以后目标上提示"买完了吗？"，点"完成"才变 `done`
- 各种操作后 `goal_id` 怎么变（照 R22.2 的表，M11-1 写进 R22.2 或 R25）：
  - 分类改成非支出口径（收入、内部转账、未分类）→ 清掉
  - 小票保存（R20.3）→ 清掉，和一次性一样提示"挂的目标已清掉，需要的话重新挂"
  - 改归属人、备注、金额、日期，pending 确认 → 不变
  - 撤销导入、删除交易 → 跟着没了
  - 写拆分的代码不要顺手把 `goal_id` 写成默认值

**完成和每年重复**

- `once`：点"完成" → `done`，从填进度里退出，后面的往前顶。进"已完成"列表，留着计划和实际
- `yearly`：点"完成" → 这一期 `done`，同时建下一期：名字、金额、账户、优先级照抄，日期 + 1 年（2 月 29 日 → 2 月 28 日）
- 已完成的可以"撤销完成"回到 `active`（`yearly` 撤销时，自动建的下一期如果还没挂交易就删掉，挂了就报错）（2026-11-03 定）
- 完成以后挂上的交易还能看，不能再挂新的
- 删除目标：没挂交易的能删；挂了的只能完成（2026-11-03 定）

**预算总览**（R11.1 加一行）

- 为目标存 = 本月"每月要存合计"（同上面的口径）
- 预算总览多一行：还剩 $X − 为目标存 $Y = **还能花 $Z**，可以是负数
- 首页预算那一行（R11.3）也加："还能花 $Z（已扣目标）"。没有目标（合计是 0）时不显示这部分
- 不改预算本身的上限和进度

**`/goals` 页**

- 不跟看板的时间段和归属人筛选
- 顶部：每月要存合计、近 3 个月实际每月存下、存不过来的提示
- 应急金单独一张卡片放最上面：目标金额（月均 × 月数）、进度、能撑几个月
- 其他 `active` 目标按优先级列：名字、类型、账户、进度条（已存 / 目标）、还差、每月要存、预计达成、过期提示；上下移动改优先级
- 要花掉的：计划和实际、挂了几笔、"完成"按钮
- 下面折叠"已完成"：计划、实际、差多少、完成日期
- 新建 / 编辑用 shadcn `Dialog` + react-hook-form + Zod
- 侧边栏加"目标"
- **不出设计图**，和 15 一样，照 `/accounts` 和看板卡片的样子做（2026-11-03 定）

**首页**

- 固定了的目标才显示，每个一张小卡片：名字、进度条、还差、每月要存
- 没固定的 → 什么都不显示，不留空位
- 不跟看板筛选

**不做**

- 一个目标挂几个账户
- 手动记每个目标存了多少（N2.3 不做虚拟拆分）
- 自动把钱分配到目标（转账提醒、定时转账）

- 按归属人分目标
- F8 按目标筛选（目标页直接列挂的交易）
