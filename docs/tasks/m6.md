# M6：手动录入和 pending

> 目标：现金和随手记的消费能当场记下来，手机上从点 + 到保存不超过 10 秒；ANZ、CBA 上记的 pending 月底导入时自动确认。
> 参考：`docs/prd.md` F3；`docs/business-rules.md` R5、R7、R8、R16.3、R16.8、R17；`fixtures/README.md`（pending 匹配用例 P1 到 P10、U6）；`docs/design/README.md`（04、05）
> 涉及页面或数据库的任务，先用 plan mode 说打算怎么做，我同意了再写。

## 通用要求

- 导入那一头（R8.2 匹配、R8.3 确认和转账例外、R8.4 待检查、`warnings.possibleDuplicates`）M3 已经做了，这次不改导入流程，只在 M6-2 用真的手动录入把 P1 到 P10 跑一遍
- 规则写成纯函数放 `src/lib/rules/`，数据层放 `src/server/`，写入用 Server Actions + Zod
- 金额解析用 `parseSplitAmountInput`（`parseAmountToCents`），不用 `parseFloat`
- merchant 用 `cleanMerchant`，归属人用 `resolveMember`，分类匹配用 `classify.ts` 里现成的函数，不另写一套
- "今天"从 `todayInMelbourne()` 来，数据层函数接收 `today` 参数
- 这个里程碑不改表结构，不加新依赖（shadcn/ui 的组件不算，用到新的先说一声）
- 弹窗关掉再打开要是干净的表单：注意 cacheComponents 的 Activity 会保留 state（tech-stack 2）
- 设计图 05 和文档不一致的地方见 `design/README.md` 第 4 节，照文档做

## 边界情况

规则文档原来没写到的几处，2026-10-25 定下来写进了 `business-rules.md` R17：

- 猜的分类、自动的归属人，用户没动就记真实来源（`rule`、`category` / `account`），点过才记 `manual`（R17.3）
- 被导入确认过的 pending 和导入的交易一样，不能编辑、删除整笔（R17.5）
- 可能重复的 pending 只提示，删掉或改掉多余的 pending 提示就消失，没有"忽略"按钮（R17.6）
- 手机上用系统数字键盘（`inputmode="decimal"`），不做设计图里的自制键盘
- 描述必填；常用分类按最近 90 天手动录入的次数；上次账户从数据库取（R17.1、R17.2）

## M6-1 手动录入规则（纯函数）

- [x] 完成

**规则**：R8.1、R17.1 到 R17.3、R17.5、R17.6
**文件**：新建 `src/lib/rules/manual.ts`

**做什么**

- `buildManualTransaction(input, ctx)`：输入表单值（金额字符串、支出 / 收入、描述、账户、日期、分类和是否猜的、归属人或"自动"），输出要写入的交易和主拆分字段，或者字段错误。包括 status（R8.1）、merchant、category_source、member_source、is_pre_tax
- `guessCategory(description, kind, rules, categories)`：R17.2 猜分类，类型不对时返回空
- `frequentCategories(recent, kind, today, n)`：R17.2 常用分类
- `canEditManual(tx)`：R17.5，返回能不能编辑、能不能删除、不能的原因
- `applyManualEdit(tx, splits, edit, ctx)`：R17.5 编辑，返回要改的字段（含状态、merchant、归属人重算），或错误（改符号、多拆分改金额）
- `activeDuplicates(warnings, pendingStates)`：R17.6，返回现在还要显示"可能重复"的交易 id

**完成标准**

- 现金账户 → confirmed；ANZ Joint、CBA Female → pending；ANZ Plus Male 记 +8.50 Income / Interest → confirmed、is_pre_tax = true、Male（account）（fixtures P7、P8）
- 描述 `coffee lab  ` → raw_description `coffee lab`，merchant `COFFEE LAB`
- 金额 `12.5` → -1250（支出）；`0`、`-5`、`1.234`、空的都报错
- 日期晚于今天报错
- 猜分类：描述含 `COLES` 时猜 Groceries / Supermarket；切换在"收入"时同样的描述不猜
- R17.3 的表每行一个测试；Joint 账户选 Groceries / Supermarket、归属人自动 → Home（category）
- `frequentCategories`：91 天前的不算；次数一样时最近用的排前面
- 编辑：有 `import_batch_id` 的不能改不能删；有 `transfer_pair_id` 的不能删；两个拆分时改金额报错；现金 → ANZ Joint 变 pending
- R17.6 的例子（删 P4、再删 P3）每一步一个测试
- 已有测试全部还能通过
