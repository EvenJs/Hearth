# M10：每月条件（F13）

> 目标：每个账户能配置每月条件（bonus interest、免月费），app 按当月流水判断"已满足 / 还差多少 / 已经失败"；`/accounts` 显示本月进度和历史；月底前没满足时首页放一条提示；"已满足"的月份出现月费时提示配置可能不对。
> 参考：`docs/roadmap.md` M10；`docs/prd.md` F13、第 6 节原则 1；`docs/proposals/2026-10-30-buckets-goals-budget.md` N2.4、N2.5；`docs/business-rules.md` R2.2、R6.1、R6.2、R8、R10、R23、**R24**（M10-1 写）；`docs/schema.md` financial_account、transaction、transaction_split、account_balance；`docs/design/README.md` 02、15
> 前置：M9（关联账户、余额锚点）。M9-7 外行转账还没做也能开始，只是那几笔认不出对方账户（见边界情况"对方账户"）。
> 涉及页面或数据库的任务，先用 plan mode 说打算怎么做，我同意了再写。

## 通用要求

- **不加依赖。** 改表只在 M10-4 一次：条件配置一张表、"其他"类型每月手动勾一张表。**改表前先问**，SQL 给我看
- 纯函数放 `src/lib/rules/conditions.ts`，不 import 数据库和 Next.js；月末余额加在 `src/lib/rules/balance.ts`（R23.7 留给 M10 的那条）；数据层新建 `src/server/conditions.ts`
- 判断结果**每次实时算，不存**（和 R23.3 差额一样）。只有"其他"类型的手动勾选要存。补导了流水，结果自己变
- 条件只看 `transaction.amount_cents`、日期、账户、对方账户，**不改任何交易的分类、转账状态**。唯一用到分类的是"月费"和"利息"（看拆分，见下面）
- 看板、F8、预算、税务、月均、余额的数字都不变
- 月份按 Melbourne 自然月，日期是 `YYYY-MM-DD` 字符串，用 `periods.ts` 的 `startOfMonth`、`endOfMonth`
- 金额显示 `formatAud`；全部带 `household_id`

## 边界情况

2026-11-03 全部定了，M10-1 写进 R24。

**条件类型**（prd F13 的五种 + 其他）

| 类型 key | 意思 | 参数 | 看哪个账户 |
| --- | --- | --- | --- |
| `min_deposit` | 当月存入至少 $X | 金额（分）、哪些存入算数 | 本账户 |
| `no_withdrawal` | 当月不取款 | — | 本账户 |
| `balance_growth` | 月末余额比上月末高 | — | 本账户 |
| `linked_min_deposit` | 关联账户当月存入至少 $X | 金额、哪些存入算数 | 本账户的 `linked_account_id` |
| `linked_card_count` | 关联账户当月刷卡至少 N 笔 | 笔数 | 本账户的 `linked_account_id` |
| `other` | 文字描述，app 判断不了 | 文字 | — |

- 一个账户可以有多个条件；每个条件有自己的结果：`bonus`（拿 bonus）或 `fee_waiver`（免月费）
- 同一个账户、同一个结果（bonus / 免月费）有多个条件时，**全部满足才算拿到**，有一个失败就没拿到。不同结果分开算（2026-11-03 定）
- 不做"任一满足"。以后真遇到"二选一"的条件，再在条件上加"全部 / 任一"
- 关联类型要求本账户有关联账户；没有关联时配置表单报错，已经配好后关联被删掉 → 这个条件显示"关联账户没设置"，不判断
- 条件可以停用（不删），停用的不判断、不提示，历史里停用之前的月份照样显示
- 配置记 `effective_from`（月份）。改金额 = 停用旧的、建新的，以前的月份照旧金额算，不按新金额重算（2026-11-03 定）
- 界面上给"添加 / 修改 / 删除"：修改 = 停用旧的、建新的；删除 = 停用。历史都保留，后台没有真删（2026-11-03 定）

**存入、取款怎么算**

- ~~只看 **confirmed** 交易（银行按入账算，pending 不算），"还差多少"里也不显示 pending（2026-11-03 定）~~ 2026-11-08 改：pending 也算，没配上的不算，见 R24.2a 和 M10-9
- 存入 = 当月 `amount_cents > 0` 的交易，**去掉利息和月费退回**（拆分上 `Income / Interest`、`Bank fees` 的部分；ANZ 的 `REVERSAL OF ACCOUNT SERVICING FEE` 是正数，不能算进 $2000）。退款算存入（2026-11-03 定；ANZ 官网没写，问到了说不算再改）
- 哪些存入算数（`min_deposit`、`linked_min_deposit` 的参数）：
  - `any`：任何存入
  - ~~`exclude_same_bank`~~：不做。ANZ 自己账户之间转账算存入（M10-0 确认），这个选项当初只为这个不确定才加（2026-11-03 定）
  - `exclude_linked`：去掉从"关联到这个账户的 saver"转回来的（`linked_account_id = 本账户` 的那些）
- 取款 = 当月 `amount_cents < 0` 的交易，去掉月费（拆分上 `Bank fees`）和利息冲正。转到自己别的账户也算取款（saver 条件一般就是这个意思）
- `no_withdrawal`：一笔取款出现就"已经失败"，写清楚哪天、多少、去哪（"3 号从 Progress Saver 转出 $200"）
- 刷卡笔数：当月 `amount_cents < 0`、不是内部转账（`transfer_status` 是 `none`）、不是月费的交易笔数（2026-11-03 定）。银行一般只算刷卡（POS / 网购），描述里分不清 BPAY，先接受多算

**对方账户**（`exclude_linked` 要用）

- 有 `transfer_pair_id` → 对方是那笔交易的账户
- 没配对但 `transfer_status` 是 auto / confirmed → 用 `storedTransferAccountId`（从脱敏描述重跑 R6.1）
- 都没有（PayID 只有人名、外行转账认不出、R6.3 还没确认的建议）→ **对方未知，按"算数"处理**（2026-11-03 定），进度旁边小字"N 笔存入认不出来自哪个账户，按算数处理"。这样不会因为认不出把条件误判成没满足

**月末余额**（`balance_growth`）

- 在 `balance.ts` 加 `balanceAt(anchors, transactions, date)`：这一天结束时的入账余额，用 `date` 当天或之前最近的锚点 + `(锚点日期, date]` 的 confirmed 交易。只看 confirmed，和 R23.3 校准一样
- 上月末或这个月末之前没有锚点 → "没有余额，判断不了"，不算失败
- 本月没结束时显示"现在比上月末多 / 少 $X"，月底才定结果

**状态**

- 每个条件每个月一个状态：
  - `met`：已满足（存入够了；刷卡笔数够了）。月中就能定，后面怎么样都不变
  - `failed`：已经失败（`no_withdrawal` 出现取款；月份过完了还没满足）
  - `in_progress`：本月还没过完、还没满足。显示"还差 $X / 还差 N 笔"
  - `unknown`：判断不了（没余额、没关联账户、"其他"还没勾）
- `no_withdrawal`、`balance_growth` 月中没失败的显示 `in_progress`（"到目前没有取款"），月份过完才变 `met`
- "月份过完" = 今天（Melbourne）已经过了这个月最后一天，不管数据导到哪天。"截至哪天"早于月底时，结果后面加"（数据截至 X 日，可能不准）"（2026-11-03 定）
- ANZ 说"当月最后一个工作日前存入"。不管工作日，按自然月（2026-11-03 定；ANZ 官网没写最后一个工作日之后存的算哪个月）；月底那几天存的钱算不算以银行收没收月费为准（见下面的月费校验）

**数据截至哪天**

- 每个账户：这个账户最晚一笔 confirmed 交易的日期，和 R23.2 "截至哪天" 取法一样但不算 pending
- 关联类型看关联账户的截至日期
- 进度、首页提示、历史都写"数据截至 X"

**"其他"类型**

- 每月一个手动勾：满足了 / 没满足 / 还没勾。存 `(condition_id, month)`
- 可以改、可以清掉
- 首页提示不管"其他"（判断不了），只在 `/accounts` 显示"还没勾"

**月费校验**（prd F13 "已满足的月份出现月费"）

- 结果是 `fee_waiver` 的条件，判断成 `met` 的月份，本账户当月 `Bank fees` 拆分的**净额**小于 0 → 提示"这个月判断满足了，但还是收了 $X 月费，条件配置可能不对"（$X 是净额的绝对值）
- 为什么看净额：ANZ 满足了也会先扣 $5（`ACCOUNT SERVICING FEE`），再退回 $5（`REVERSAL OF ACCOUNT SERVICING FEE MINIMUM $2000 IN DEPOSITS RECEIVED`），两笔都在流水里（M10-0 看真实流水确认）。扣了又退的净额是 0，不提示
- ANZ 月费在**当月最后一个工作日**扣（费用册写的；碰上非工作日提前，不会跨月），退回也在同月。所以只看同一个月（`[月初, 月末]`）里的 `Bank fees`
- 只看 `Bank fees` 分类的拆分，金额不限（别的手续费也会被提示，先接受）
- 反过来"没满足但没收月费"不提示（可能银行宽限，也可能是 app 判断错，先不管）
- 结果是 `bonus` 的不做校验（bonus 利息和基础利息在流水里分不开）

**首页提示**（prd 第 6 节原则 1）

- 只在本月最后 5 天（含最后一天）出现，天数写成常量（2026-11-03 定）
- 有 `in_progress` 的条件（不含 `other`、`unknown`）才出现，**只放一行**：一个条件 → "Progress Saver 本月还没存入，还差 $10（数据截至 11-26）"；多个 → "2 个账户条件本月还没满足（数据截至 11-26）"
- 点了跳 `/accounts`
- `failed` 的不提示（已经来不及了），在 `/accounts` 看
- 不放条件卡片，不跟看板的时间段和归属人筛选

**`/accounts` 上怎么显示**

- 有条件的账户卡片下面加"本月条件"：每个条件一行，类型说明 + 状态 + 还差多少 / 失败原因
- 历史：最近 12 个月，每月一个小格（满足 / 失败 / 判断不了），点开看那个月每个条件；有月费校验提示的月份标出来
- 历史从条件 `effective_from` 开始，之前的月份不显示
- 历史里每个月显示那个月的 `Income / Interest` 合计（N2.4 "配合利息看实际赚了多少"），R23.6 的算法按月算（2026-11-03 定）

**配置放哪**

- 配置在 `/settings/accounts` 的账户编辑里（M9 定的：设置页只管配置），`/accounts` 只显示进度和勾"其他"
- 现金账户、`other` 银行的账户也能配（中转账户一般不用），不限制

**不做**

- 内置银行条件模板（app 不知道哪家银行是什么条件）
- 自动推荐"这个月取钱还是下个月取"（只显示状态，你自己判断）
- 固定周期转账自动确认（N2.5 提过，开始前再定，不在 M10）
- 按工作日算月底
- bonus 利息的预估金额
