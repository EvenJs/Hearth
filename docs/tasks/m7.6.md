# M7.6：小票商品类型统计

> 目标：小票上每件商品有一个商品类型（水果、肉、零食……），按月看各类型花了多少。类型只存在小票明细里，**不参与拆分，不影响分类、看板、预算**。不用 AI，关键词规则 + 学习。
> 参考：`docs/roadmap.md` M7.6；`docs/business-rules.md` R7（思路）、R13（从手动修改学习的思路）、R20.2、R20.3、R20.7、**R21**（M7.6-1 写）；`docs/schema.md` receipt；`fixtures/README.md` 小票用例
> 涉及页面或数据库的任务，先用 plan mode 说打算怎么做，我同意了再写。

- **不加依赖。** 只加一张学习表（M7.6-4），**改表前先问**，SQL 给我看

- 全部带 `household_id`

## 边界情况

拆任务时先这么定，M7.6-1 写进 R21，不对就改：

- 每件商品都有类型，包括 LLM 给了分类的（洗发水 → 日用）。类型和分类是两回事，互不推导
- 负数商品（单件折扣）跟上一件商品的类型，第一行就是负数时 → 其他（同 R20.3 第 1 步的思路）
- 整单折扣按各类型金额比例分摊（同 R20.3 第 3 步），这样各类型合计 = 小票总额
- 匹配顺序：学到的（商品名完全相同，规范化后比） > 预置关键词（包含，关键词长的优先） > 其他
- 学习只在**用户手动改了**某件商品的类型时发生；自动认出来的不写表。同名再改一次就覆盖，最后一次为准
- 学错了：下次在核对界面改掉就覆盖。**不做**学习规则的管理页
- 旧小票的 items 没有类型 → 统计里单独一行"未分"，和"其他"分开
- 统计按 `receipt_date` 的月份，全家，不分归属人（类型不在拆分上，没有归属人）
- 统计只算挂上了交易的小票（没挂上的可能是撤销导入留下的，等挂回去再算）。2026-10-31 定，以后再看
- LLM reader 不给类型，prompt 不改

类型列表（2026-10-31 定，共 10 个）：

| key | 中文名 | 例子 |
|---|---|---|
| `fruit` | 水果 | 香蕉、奇异果 |
| `vegetable` | 蔬菜 | 生菜、土豆 |
| `meat` | 肉 | 肉末、鸡腿 |
| `seafood` | 海鲜 | 三文鱼、虾 |
| `dairy_egg` | 乳制品和蛋 | 牛奶、奶酪、鸡蛋 |
| `pantry` | 主食干货 | 米、面、面包、罐头、调料酱料 |
| `snack` | 零食 | 薯片、饼干、巧克力 |
| `drink` | 饮料 | 果汁、汽水、酒 |
| `household` | 日用 | 纸巾、洗洁精、洗发水、牙膏、药 |
| `other` | 其他 | 都没认出来的 |

- 不单独分面包、冷冻、个护和药。冷冻的按食物本身归（冷冻虾 → 海鲜，速冻饺子 → 主食干货，冰淇淋 → 零食）

- 统计放看板，加一块（2026-10-31 定，以后再调整）
- 交易详情的小票明细里能改类型：只改类型并学习，不改金额、分类，拆分不动。旧小票可以这样补类型（2026-10-31 定）
