## 边界情况

拆任务时先这么定，M7.7-1 写进 R22，不对就改。原来要拍板的几条 2026-11-01 定了，按下面写。

**一次性标记**

- 标记三种状态：没看过（`null`）、是（`true`）、确认不是（`false`）。为什么要三态：房贷、房租每个月都超过 $500，只有是/否的话"大额未标"会永远提示。统计里 `null` 和 `false` 一样，都不算一次性
- 只有支出口径的拆分能标（R10：kind = `expense`，加上现金支出、银行费用）。拆分改到非支出分类时标记清成 `null`
- 拆出一部分（R15.2）：新拆分默认 `null`，拆分对话框里可以直接勾；主拆分保持原来的
- 改非主拆分金额（R15.3）：两边标记都不变。删除非主拆分：它的标记跟着没了，主拆分的不变
- 规则重新应用（R7.2）、R16.4 改分类、批量改分类：标记不动，除非改成了非支出
- pending 确认（R8.3）：保留
- 小票保存（R20.3）重排拆分：新建出来的拆分都是 `null`；原来标过"是"的，保存后提示一句"一次性标记已清掉，需要的话重新勾"
- 不做批量标一次性（批量本来就跳过多拆分交易）
- 退款：一次性买的东西退了，退款那条也要手动标"是"，不然会冲减月均。只靠用户自己标，不自动配

**大额未标提示**

- 阈值先定 $500，写成常量 `ONE_OFF_HINT_CENTS = 50000`。prd 说"可以改"，先等于改常量，不做设置页。具体数字 M7.7-0 看真实流水再调
- 按交易算（同 R10.3，一笔算一次）：这笔交易支出口径拆分合计 ≤ −50000，且这些拆分全是 `null` → 提示
- 只要有一个支出拆分是 `true` 或 `false` 就不提示（用户看过了）
- 交易详情的提示上有"是"和"不是一次性"两个按钮，点"不是"把这笔所有 `null` 的支出拆分设成 `false`
- 转账、收入、未分类不提示；pending 照样提示
- F8 列表行上一个小标"一次性？"，快捷筛选加"大额未标 N"。点进详情去勾，不自动标

**F8 筛选**

- 加"一次性"筛选：全部 / 是 / 否（否 = `null` + `false`）。合计只加命中的拆分（R16.5）

**月均**

- 完整月：今天所在月之前的月份（`Australia/Melbourne`）。近 12 个月窗口最多 12 个，近 3 个月最多 3 个
- 数据起点：本家庭最早一笔交易所在的月份，不管是不是 1 号。窗口里早于起点的月份不算；月数 = min(12, 起点月到上个月的月数)。0 个月 → 卡片显示"还没有完整月的数据"
- 月均 = 窗口内支出合计 ÷ 月数。某个分类有几个月是 0 也算进月数，所以各分类、各归属人的月均加起来 = 总月均
- 口径同 R10：退款冲减，pending 计入，转账、交税不算，未分类不算；**另外排除 `true`**
- 取整：总月均四舍五入到分；各一级、各归属人的月均用最大余数法分配，加起来正好等于总月均；二级在它的一级里再分一次。小票整单折扣分摊（R20.3 第 3 步）如果能复用就复用，要提公共函数先说
- 归档分类的支出照算，列表里照列，标"已归档"
- 维度：一级（可展开二级）、归属人。跟看板的归属人筛选（R10.6），不跟时间段（同 R10.5）
- 本月对比：本月 = 本月 1 日到今天，也排除一次性（和月均同口径；本月实际花了多少看 KPI 和"其中一次性"）。百分比 = (本月 − 近 12 个月月均) ÷ 月均，四舍五入同 R10.4；月均 ≤ 0 显示"—"。标一句"本月到今天，还没过完"
- 本期支出"其中一次性 $X"：跟时间段和归属人，X = 本期 `true` 的支出拆分合计（退款冲减），X 是 0 不显示

**预算默认值**

- 新建预算选了分类后，上限默认填这个分类近 12 个月的月均（一级含二级；现金支出也一样），四舍五入到整元
- 月均 ≤ 0 或没有完整月 → 不填，留空
- 用户已经动过上限就不再覆盖；编辑预算不填
- 月均按全家算，不按归属人
- 输入框下面一行小字"近 12 个月月均 $X（基于 N 个月）"。设计图里的"参考上月实际"仍然不做（design README 10）
