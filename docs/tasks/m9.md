## 边界情况

拆任务时先这么定，M9-1 写进 R23。2026-11-02 全部定了，不对就改。

**锚点**

- 两种来源（2026-11-02 定：以后都优先用 PDF，CSV 的余额先不考虑）：
  - PDF 批次（ANZ R1C、ANZ Plus R1D）：`closing_balance_cents`，日期 = `date_to`（账期结束日）
  - 手动填的：金额 + 日期
- 所有锚点的含义都是"**这一天结束时**的余额"。R1C 是 `(periodFrom, periodTo]`、R1D 是 `[periodFrom, periodTo]`，结束日都包含在内，所以 `date_to` 当天的交易已经在余额里
- **CSV 批次不当锚点**：CBA CSV 的余额列、ANZ CSV 手填的期末（R9）都不用。CSV 导进来的交易照样算进"锚点之后的交易"
- **以对账单为主**（2026-11-02 定）：PDF 期末是银行给的正本，最可信；CBA 也换成导 PDF（见下面"CBA 对账单"）；手动只是兜底，给没有对账单的账户（现金、中转）和两份对账单之间想核对一下的时候用
- 用哪个锚点：日期最晚的。同一天有几个 → PDF > 手动；同一种来源再按 `created_at` 最晚的
- **以后新建的账户**（2026-11-02 定）：新建表单有"开户余额"，默认 $0。保存时自动写一条手动锚点，日期 = 建账户的**前一天**（这样建账户当天的交易也算进去）。开户余额不是 0 就改这一项。现金账户新建时也一样，填钱包里现在有多少
- **已有的、没有锚点的账户**（现金、CBA 对账单做完前的 CBA、已经建好的中转账户）：**不显示余额**，显示"还没有余额，填一次"，不算进合计。不从 0 开始累加，因为建账户以前的钱 app 不知道。现金账户就靠手动填
- 只有新建时自动写锚点，迁移**不**给已有账户补 $0 锚点

**当前余额**

- **两个余额**（2026-11-02 定，像银行的"余额 / 可用余额"）：
  - **入账余额** = 锚点金额 + 这个账户 `date > 锚点日期` 的 **confirmed** 交易合计。和网银的余额对应
  - **可用余额** = 入账余额 + 锚点之后的 **pending** 合计。月中录的小票（R20.5 新建的 pending）、手动录入的消费会马上减到这里，不用等导入或对账单
  - 没有 pending 时两个数一样，只显示一个；有 pending 时大字是可用余额，下面小字"入账 $X，含 N 笔待确认 $Y"
  - 不会重复算：导入 CSV 或对账单时 R8.2 把 pending 配上银行那笔，变成同一笔 confirmed，可用余额不变、入账余额跟上。pending 没配上的会和银行那笔重复，F8 已经提示"可能重复"（R17.6），删掉多的就对了
  - 现金账户的手动录入直接是 confirmed（R8.1），两个数一样
- 截至哪天 = max(锚点日期, 之后最晚一笔交易的日期)，pending 也算
- 锚点日期当天、但锚点之后才导进来的交易：不算（按定义已经在锚点里）。所以手动校准要填"某天结束时"的数
- 手动校准的日期：默认填**昨天**，可以改。旁边一行小字"填这一天结束时网银显示的余额；今天的交易可能还没全部入账，所以默认昨天"
- 归档的账户：不显示，不算合计
- 信用卡：余额是负数，照样加进合计

**手动校准和对不上的提示**

- 填手动余额时，用它前面最近的那个锚点算出这一天的预期余额：预期 = 前一个锚点 + `(前一个锚点日期, 这一天]` 的已确认交易合计。**和入账余额比，不算 pending**（网银的余额不含 app 里还没入账的那些）
- 预期 ≠ 填的数 → 保存后提示"和算出来的差 $X，可能漏导了交易"。**照样保存**，填的数成为新锚点
- 差额**每次实时算，不存**：后来把漏的交易补导进来，预期变了，提示自己消失
- 账户卡片上只看最近一次手动校准：有差额就显示"上次校准差 $X"
- 手动锚点前面没有任何锚点（第一次填）→ 不比较，不提示
- 手动余额可以删（填错了）。不能改，删了重填
- 手动余额的日期可以早于最近的 PDF 锚点（比如补填半年前的数）：它只是一个更早的锚点，不影响当前余额，只参与对比

**用途和关联账户**

- 用途枚举：`everyday`（日常）、`bills`（账单）、`emergency`（应急金）、`savings`（储蓄 / 高息）、`goal`（目标）。和 `type` 分开（prd F12）
- 已有的账户：`not null default 'everyday'`，迁移后自己在设置页改
- 现金账户也有用途（一般是日常），不特殊处理
- 关联账户：一个账户最多关联一个，可以不关联。不能关联自己、不能关联别的家庭的、不能关联已归档的、现金账户不能关联也不能被关联
- 不限定"saver 才能关联 everyday"：用途、类型不做组合限制，M10 用到再说
- 被关联的账户归档了：关联不动，显示"（已归档）"

**账户总览 `/accounts`**

- 分组顺序：日常、账单、应急金、储蓄 / 高息、目标；空的组不显示
- 每组显示组合计；页面顶部显示所有账户余额合计。合计用**可用余额**，下面小字"入账合计 $X"（有 pending 时才显示），"不含 N 个还没有余额的账户"（N 是 0 不显示）
- 每个账户：名字、银行、尾号、余额、截至哪天、锚点来源（"对账单期末" / "手动填的"）、关联账户、利息
- 利息：**本财年**（7 月 1 日到今天，Melbourne）这个账户上分类是 Income / Interest 的拆分合计（退款冲减同 R10）。为什么本财年：利息要报税（seed-categories 里 Interest 计入应税收入）
- 账户总览不跟看板的时间段和归属人筛选
- 侧边栏加"账户"入口；手机上能打开就行

**中转账户和外行转账（N2.5）**

- 中转账户建成 `bank = other`，填尾号，用途按实际（一般是日常）
- ANZ 转到外行的描述格式**还没见过**。R2.2 现在认 `TRANSFER ... TO/FROM [BSB-]账号`。M9-0 拿第一笔真实流水看：能认出来就不改代码，只在 R2.2 补一条"外行转账已确认"；认不出来再做 M9-7
- 另一侧（BOQ、Westpac）没有流水，配不上对没关系（R6.2 找到 0 笔不影响 auto，和 ANZ Plus 一样）
- 钱放过月底的话，中转账户用手动余额，否则不填
- **BOQ、Westpac 以后也会有日常花销账户和存款账户**（2026-11-02）。那时就不只是中转了，要有流水、有余额，得给这两家写解析器（优先 PDF 对账单，同 CBA），`bank` 枚举也要加值。**不在 M9 里做**，等有了真实对账单再单独加里程碑。M9 期间它们按 `bank = other` 建，余额靠手动

**CBA 对账单**

- CBA 对账单解析器**不在 M9 里做**，是一个新的解析器（像 R1C、R1D），要先拿真实对账单看格式、写规则，单独一个里程碑 **M8.5**，排在 M9 前面

- CBA 对账单还没做完的话，CBA 账户只能靠手动余额，没填就显示"还没有余额"

**小票**

- 小票不影响余额：小票只是挂到已有的交易上，拆分商品（R20），金额来自那笔交易。现金消费靠手动录入（F3）进现金账户，算在锚点之后的交易里

**不做**

- 自动从余额差反推漏导了哪几笔
