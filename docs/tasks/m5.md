## 通用要求

- 统计口径只用 `src/lib/rules/stats.ts` 和 `periods.ts`（M2 已有 `summarize`、`pivot`、`periodRange`、`previousPeriod`），新的计算也写成纯函数，不在 SQL 里算业务口径
- `src/server/dashboard.ts` 只负责按 `household_id` 把拆分查出来、串起纯函数
- "今天"从 `todayInMelbourne()` 来，数据层函数接收 `today` 参数，方便测试
- 时间段、归属人、汇总表的切换都放 URL 参数，刷新和分享不丢；跳 F8 用 `filtersToSearchParams`
- 这个里程碑不改表结构
- 置顶预算（F7）、税务卡片（F9）是 M7，这次不做，也不留空占位
- 设计图 02 和文档不一致的地方见 `design/README.md` 第 4 节，照文档做

## 边界情况

规则文档原来没写到的几处，2026-10-24 定下来了：

- Top 商家、对比上期、近 12 个月趋势、归属人筛选和 pending：写进了 `business-rules.md` R10.3 到 R10.6，期望值在 `fixtures/README.md`"看板"一节
- Top 商家**按笔数**排（R10.3）
- 趋势图只画收入、支出柱子加净额线；PRD 里"各分类每月变化"先用汇总表"按月 × 分类"代替
- 汇总表在手机上放在自己的横向滚动容器里，页面本身不横向滚动，算"能用"
- F8 商家筛选是"包含"，点 COLES 可能带出 COLES EXPRESS。先接受，不加精确匹配
- KPI 卡片（M5-3 时定的）：
  - 未分类卡片**不放**对比上期，照 R10.4。任务原文"每张带对比上期"指收入、支出、储蓄率三张
  - 储蓄率是比率不是合计，F8 也没有"收入加支出"的类型，所以储蓄率**不能点**。其他数字都能点
  - "其中税前"能点：跳 F8 的收入加 `税前 = 是`（`kpiLink` 的 `pre_tax`）
  - 储蓄率取整显示（如 `25%`），舍入方式同 R10.4（按绝对值舍入再带符号）
  - 看板 URL 参数和 F8 一样（`period` 或 `from`/`to`、`member`）；本月是默认，不写进 URL；URL 里的归属人不是本家庭的，当作没选
