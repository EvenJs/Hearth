# M12：邀请码注册（F15）

> 目标：注册一直开着，但必须有有效邀请码。`join` 码进发码人的家庭（发码时指定归属人），`new_household` 码只有站长能发，注册后自动建家庭、预置分类和规则；要验证邮箱，没验证不能登录；有忘记密码、改密码、改名字；小票 LLM 识别每个家庭每月 50 次。
> 参考：`docs/roadmap.md` M12；`docs/prd.md` F15；`docs/proposals/2026-11-04-signup-invite.md`；`docs/tech-stack.md` 第 4、7、8 节；`docs/business-rules.md` R20.1、**R26**（M12-1 写）；`docs/schema.md` 第 2 节、household、household_user、member
> 前置：无。不依赖 M8.5-4b、M9-7 这些等数据的任务。
> 编号：规则用 R26；fixtures 用 17 号。
> 涉及页面或数据库的任务，先用 plan mode 说打算怎么做，我同意了再写。

## 通用要求

- **只加一个依赖 `nodemailer`**，在 M12-4 装（10.x 自带类型，不装 `@types/nodemailer`，M12-4 定）。别的都用 Better Auth 自带的
- 改表只在 M12-3 一次。**改表前先问**，SQL 给我看
- 纯函数放 `src/lib/rules/invite.ts`、`src/lib/rules/llm-quota.ts`，不 import 数据库和 Next.js；数据层新建 `src/server/invites.ts`、`src/server/llm-usage.ts`；发邮件放 `src/server/email.ts`
- 邀请码校验、建用户、建 `household_user`、新家庭 seed、把码标成已用：**同一个事务**，任何一步失败全部回滚
- 邀请码、密码、重置链接不打日志
- 时间按 `Australia/Melbourne`：过期看 `expires_at`（timestamptz）；限额按 Melbourne 自然月，用 `periods.ts`
- 错误提示中文，不暴露"这个邮箱已注册"之外的内部原因
- 全部业务查询带 `household_id`；注册页、忘记密码页是登录前的页面，不走 `getHouseholdContext`

## 边界情况

M12-0 拍板，结论写进 R26。

- **现有用户的 `email_verified`**：你和老婆是 `user:create` 建的，`email_verified` 现在大概是 `false`。开了"没验证不能登录"会把你们锁在外面。倾向：M12-3 的迁移里把现有用户都设成 `true`
- **注册怎么接 Better Auth**：
  - a. 保留 `disableSignUp: true`，注册走自己的 Server Action，照 `scripts/create-user.ts` 用 `$context` 建用户和密码，和邀请码在同一个事务里
  - b. 打开注册接口，在 `databaseHooks.user.create.before` 里校验邀请码
  - 倾向 a：b 拿不到我们自己的事务，码和用户可能一个成功一个失败。a 用的 `$context` 是半内部 API，升级 better-auth 要重测（`create-user.ts` 已经有这个问题）
- **新家庭的分类默认归属人**：`seed/data.ts` 的分类默认归属人是 `Male` / `Female` / `Home`，新家庭只有"注册的人"和"共同"。倾向：`Male`、`Female` 都映射成注册的人，`Home` 映射成共同
- **新家庭的归属人叫什么**：注册的人用他填的名字，共同叫"共同"还是 `Home`
- **新家庭名字**：注册时填，还是默认"<名字>的家"
- **同一个邮箱已经注册**：提示"这个邮箱已经注册了，去登录"，码**不作废**
- **码大小写和格式**：`HX7K-29QD` 这种，8 位，去掉容易混的 `0O1IL`，输入时忽略大小写和空格、横杠
- **两个人同时用一个码**：只能成功一个（条件 UPDATE `used_at is null` 返回行数，或者 `SELECT ... FOR UPDATE`）
- **码过期、撤销、已用**：分别提示，不建账号
- **`join` 码指定的归属人被归档了**：注册时还能用吗。倾向：能用，进来以后自己改
- **一个归属人能不能对应两个登录用户**：比如两个人都关联 Home。倾向：允许，不加 unique
- **站长自己发 `join` 码**：和普通用户一样
- **`ADMIN_EMAILS` 没配**：没人能发 `new_household`，界面上不显示这个选项
- **验证邮件没收到**：登录页"重发验证邮件"；同一个邮箱多久能重发一次
- **验证链接、重置链接多久过期**：Better Auth 默认 1 小时，够不够
- **重置密码后**：别的设备上的 session 要不要全部退出。倾向：退出
- **改邮箱**：这次不做
- **小票限额算什么**：每次真的调用 LLM 算一次，不管成功失败、存没存；LLM 没配（`RECEIPT_READER=none`）不算；粘贴文字、手动填不算
- **到了 50 次**：识别按钮变灰，写"本月识别次数用完了，X 月 1 日恢复"，粘贴文字和手动填照常
- **限额是家庭的还是人的**：家庭的，两个人一起用 50 次
- **Gmail 发不出去**（密码错、超额）：注册成功但提示"验证邮件没发出去，请联系站长"，站长可以用 `user:create` 或者 SQL 补救

### 结论（M12-0，2026-11-08 定）

M12-1 照这里写进 R26。

- 现有用户：M12-3 的迁移里把现有用户的 `email_verified` 都设成 `true`
- 注册接 Better Auth：方案 a。保留 `disableSignUp: true`，自己的 Server Action 用 `$context` 建用户，和邀请码在同一个事务
- 新家庭分类默认归属人：`Male`、`Female` → 注册的人；`Home` → 共同
- 新家庭归属人：注册的人用他填的名字；共同叫"共同"
- 新家庭名字：注册时不填，默认"<名字>的家"，以后在设置页改
- 同一个邮箱已经注册：提示"这个邮箱已经注册了，去登录"，码不作废
- 码格式：8 位，显示成 `XXXX-XXXX`，字符集去掉 `0O1IL`；输入忽略大小写、空格、横杠
- 两个人同时用一个码：只能成功一个
- 码过期、撤销、已用：分别提示，不建账号
- `join` 码指定的归属人被归档了：照样能用，进来以后自己改
- 一个归属人可以对应多个登录用户，不加 unique
- 站长发 `join` 码：和普通用户一样
- `ADMIN_EMAILS` 没配：没人能发 `new_household`，界面不显示这个选项
- 重发验证邮件：登录页有"重发验证邮件"，同一个邮箱 60 秒一次
- 链接过期：验证链接 24 小时，重置链接 1 小时
- 重置密码后：其他设备的 session 全部退出
- 改邮箱：这次不做
- 小票限额：真的调用 LLM 才算一次，不管成功失败、存没存；`RECEIPT_READER=none`、粘贴文字、手动填不算；按家庭算，每月 50 次（`RECEIPT_LLM_MONTHLY_LIMIT`），Melbourne 自然月
- 到了限额：识别按钮变灰，写"本月识别次数用完了，X 月 1 日恢复"，粘贴文字和手动填照常
- Gmail 发不出去：注册成功，提示"验证邮件没发出去，请联系站长"
