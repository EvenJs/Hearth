## 边界情况

2026-10-28 定下来、已经写进规则文档的：

- PDF 和 CSV 混着导，靠 R4 去重；ANZ 的 key 不放余额（R1C、R4.1）
- 余额对不上整份拒绝，不像 CBA 只警告（R1C）

- 一笔交易都没有的对账单也能导入（R1C）

- 账期是 `(periodFrom, periodTo]`，`date_from` 存开始日的第二天（R1C）。这是从 `OPENING BALANCE` 的日期推的，首日出现交易就报错，提醒回来改规则

## M6.6-3 读 PDF 文字

- [x] 完成 🔒 M6.6-2

**规则**：R1C 第一层
**文件**：新建 `src/server/pdf/text.ts`；`package.json`（`unpdf`）；`tests/local/statement-try.ts`（不提交）

**做什么**

- `pnpm add unpdf@<定死的版本>`。装之前查一下最新版发布满两周没有，没满就用上一个版本
- `extractPdfLines(buffer)`：用 unpdf 拿每页的文字块和坐标，按 y 分行、按 x 排序；同一行里两块之间的空隙大于一个字符宽就放两个空格，否则一个空格。返回 `{ page, text }[]`
- 读不出文字（扫描件、加密的）→ 返回失败"读不出文字"
- 本地脚本：读 `tests/local/` 里的真实对账单和同账期 CSV，跑 `extractPdfLines` + `parseAnzStatement` + `parseBankCsv`，只打印"多少行对上了、对不上的是哪类差异"（数字、字母遮掉），不打印内容

**完成标准**

- Access Advantage 那份：50 行全部和 CSV 对上，三项检查都通过（2026-10-28 用 `pdftotext` 试过是这样，换成 unpdf 后要还是这样）
- Joint、Progress Saver 那两份（M6.6-0 放了的话）：能解析，检查通过。不行就告诉我哪里格式不一样，先改 R1C 再改代码
- 一个随便的、不是对账单的 PDF：`parseAnzStatement` 失败，不崩
- Vercel 预览环境上能跑（`unpdf` 在 serverless 里能用）
