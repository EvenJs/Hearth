# M3：导入流程

> 目标：在页面上导入 ANZ、CBA 的 CSV，数据进数据库，能看结果、能撤销。
> 参考：`docs/business-rules.md` R1 到 R12、`fixtures/README.md`、`docs/design/README.md`（06、07、08）、`CLAUDE.md` 数据库部分
> 涉及页面或数据库的任务，先用 plan mode 说打算怎么做，我同意了再写。

## 通用要求

- 业务判断全部用 M2 的纯函数，`src/server/` 只负责读写数据库和串流程
- 导入和撤销都在**一个事务**里（`db.transaction`），任意一步出错全部回滚
- 不保存上传的 CSV 原文件；日志、报错里不打印原始描述
- 这个里程碑不改表结构。真的需要时先停下来问我

## M3-1 规则补丁（纯函数）

- [x] 完成

**规则**：R6.3、R8.3 例外、R12.1（2026-10-23 新增的部分）
**文件**：`src/lib/rules/transfer.ts`、`src/lib/rules/pending.ts`、`src/lib/rules/extract.ts`、新建 `src/lib/rules/undo.ts`

**做什么**

- `suggestTransfers` 加参数：本次新插入的交易 id。只建议至少一边是新交易的配对；候选仍然从整个家庭里找，"两边互相只有对方一个候选"也按整个家庭算
- 从**脱敏后**的描述里提取尾号：`****1234` → `1234`，只在含 `FUNDS TFER` 或 `TRANSFER` 时提取（撤销时重跑 R6.1 用）
- R8.3 例外：pending 被确认时，银行那行 R6.1 认出是转账 → 返回要改的字段（transfer_status、主拆分分类、category_source）；pending 有多个拆分时不改，返回"需要提示"
- `planUndo(...)`：输入被撤销批次的交易、它们配对的另一半、家庭账户；输出每个另一半要怎么改（R12.1 的四种情况），以及弹窗要显示的笔数（手动改过的、确认的 pending）

**完成标准**

- R12.1 表格四种情况各有测试，包括 `****0002` 重跑 R6.1 能认出、PayID 描述认不出
- 拒绝过的 suggested（两边都是旧交易）不会再被建议；一边是新交易时照常建议
- P10 的字段变化有纯函数测试
- M2 的已有测试全部还能通过

## M3-3 导入：写入新交易和匹配 pending

- [x] 完成 🔒 M3-1、M3-2

**规则**：R12 第 1 到 5 步、R4.2、R8.2、R8.3、R1B
**文件**：`src/server/imports.ts`

**做什么**

- `importCsv(ctx, { accountId, fileName, text, openingBalanceCents?, closingBalanceCents? })`
- 账户不能导入（R1 表格）→ 直接拒绝（P9）
- 解析和逐行处理用 `processFile`；按 `(account_id, dedupe_key)` 跳过已有的

- CBA：余额警告写进 `warnings`，期初期末自动填

**`warnings` 的结构**（jsonb，不改表）：`{ balance: [...], possibleDuplicates: [{ transactionId, pendingIds }] }`

**完成标准**
