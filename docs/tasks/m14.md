# M14：工资按年薪折算、利息填全年预计（F9 补充）

> 目标：设置页不用再自己算工资总额。每份工作填年薪和在职日期，app 折算到财年底，已代扣也能估；填了实际数就用实际数。每人每财年可以填"预计全年利息"。看板税务卡没填工资时不再大字显示补税，利息没填预计时写清楚"只算到哪天"。

> 前置：无。和 M13 互不依赖。
> 编号：规则用 R14.9、R14.10，改 R14.3、R14.6、R14.8；fixtures 用 18 号。

## 通用要求

- 不加依赖
- 改表只在 M14-3 一次。**改表前先问**，SQL 给我看。`tax_profile` 两个字段去掉 not null 是 ALTER，要单独指出来
- 纯函数放 `src/lib/tax/`，不 import 数据库和 Next.js；数据层在 `src/server/tax.ts`
- 金额整数分；日期是 `YYYY-MM-DD` 字符串，天数用 `periods.ts` 的工具算，不转 `Date`
- 折算用对应财年的税率表，没有表时照 R14.7 报错

## 边界情况（方案里已经定的，M14-1 照写进 R14）

- 折算算到**财年底**：结束日期空 = 6 月 30 日
- `tax_profile` 的工资总额、已代扣各自可以为空：不为空 = 实际数，覆盖折算；空 = 用折算
- 已有的 `tax_profile` 行原样保留，照旧生效
- 预计全年利息存在 `tax_profile` 上，按人填；利息部分 = max(预计, 已到账)
- 一份工作跨财年存一行，每个财年各自折算
- 同一时间两份工作照样都算，不报错；折算已代扣不考虑第二份工作没有免税额度
- 年薪不含 super；开始日期晚于结束日期保存时报错
- R14.8 清除：还是删整行（工资总额、已代扣、预计利息一起清），在职段不受影响
- 还要 M14-1 写清楚的：在职段的删除要不要确认（倾向要）；财年天数 365 / 366
