> 目标：在页面上查流水、改分类和归属人、存规则、确认建议转账、拆分。导入后的"收拾"工作都在这里完成。
> 参考：`docs/prd.md` F8、F10；`docs/business-rules.md` R5.1、R6.3、R7、R7.2、R10、R13、R15、R16；`fixtures/README.md`（R5.1 重算、拆分、R6.3 确认和拒绝）；`docs/design/README.md`（03、04）
> 涉及页面或数据库的任务，先用 plan mode 说打算怎么做，我同意了再写。

## 通用要求

- 业务判断用 `src/lib/rules/` 的纯函数，`src/server/` 只负责读写数据库和串流程
- 改多行的操作（批量修改、应用规则、拆分、确认 / 拒绝转账）都在**一个事务**里
- 分类和归属人改的是 `transaction_split`，不是 `transaction`
- 这个里程碑不改表结构。真的需要时先停下来问我
- 设计图 03、04 里有很多文档没有的东西（见 `design/README.md` 第 4 节），照文档做

## M4-1 规则补丁（纯函数）

- [x] 完成

**规则**：R5.1、R6.3、R7、R7.2、R16.2、R16.3、R16.4、R16.5
**文件**：`src/lib/rules/transfer.ts`、新建 `src/lib/rules/split-edit.ts`

**做什么**

- `changeCategory(split, newCategoryId, ctx)`：手动改分类 → `category_source = manual`、`is_pre_tax` 按新分类默认（R7）、归属人按 R5.1 重算（`manual` 不动）
  - 新旧分类相同 → 原样返回，什么都不改（R5.1 只在分类改变时重算）
  - 交易是 `auto` / `confirmed` 转账 → 返回错误（R16.2）
  - 新分类是内部转账，或不在可选范围内 → 返回错误（R16.3）
- `changeMember(split, memberId)`：`member_source = manual`
- `resolveSuggestion(a, b, 'confirm' | 'reject', categories)`：R6.3 表格，两边各返回要改的字段
- `planReapply(txs, rules, categories, ctx)`：R7.2。只动 `category_source = rule` 的，和分类是未分类的（未分类的来源是 `system`）；其他 `system` 的（内部转账、现金支出、银行费用）和 `manual` 的不动；多拆分的跳过；分类变了按 R5.1 重算归属人。返回要改的拆分和跳过的笔数
- 分类下拉的可选项（R16.3）、交易类型的判断（R16.5）也写成纯函数

**完成标准**

- fixtures/README 的 R5.1 重算两步有测试
- fixtures/README 的 R6.3 确认、拒绝两个用例的字段变化有测试
- R7.2：未分类（来源 `system`）的能被新规则改掉；`manual`、银行费用（`system`）、多拆分各有一个"不动"的测试
- `changeCategory`：分类没变时不改 `category_source`；`auto` 转账改分类报错；选内部转账报错
- M2、M3 的已有测试全部还能通过
