# Hearth 需求文档

> 项目名：Hearth（家庭记账 App）
> 状态：需求确定，技术栈确定，准备开发（2026-10-22 更新：分类列表、归属人含义、汇总表、税后估算）
> 用户：家庭使用（我和老婆，以后可能有孩子）。MVP 阶段只有我录入和查看
> 目标：快速能用
> 背景：配合《理财学习计划.md》，替代阶段 1 用 Google Sheets 手动记账的做法

---

## 1. 背景和目标

- 我在系统学习个人理财（兴趣向，自用）
- 学习计划第一步是整理收支、做预算，需要一个记账工具
- 我是全栈开发者，想自己做一个，顺便当作作品
- 资金来源（2026-10-22 确认，账号尾号和卡号在 app 里配置，不写进文档）：

| 归属          | 账户                                   | 银行     | 怎么进数据                 |
| ------------- | -------------------------------------- | -------- | -------------------------- |
| Male          | Access Advantage（日常）               | ANZ      | 导入 CSV                   |
| Male          | Progress Saver（储蓄，和上面同一张卡） | ANZ      | 导入 CSV                   |
| Male          | ANZ Plus（存钱拿利息）                 | ANZ Plus | 不能导 CSV，每月手动记利息 |
| Home          | Joint account（Access Advantage）      | ANZ      | 导入 CSV，两人各一张卡     |
| Female        | 日常账户                               | CBA      | 导入 CSV                   |
| Male / Female | 现金（各一个）                         |          | 手动录入                   |

- Bankwest 先不考虑
- 收入：我是工资；老婆有工资，也有一部分 B2B 收入（税前，按发票收款）

**目标**

- 不手动逐笔记账，而是定期导入银行流水
- 现金收支和随手记的消费可以手动录入
- 自动分类支出，看清楚钱花在哪
- 区分每笔收支**用在谁身上**：Male（我）、Female（老婆）、Home（家庭共同），以后加 Kid
- 按周、按月汇总，按分类、按人求和
- 标记税前收入，估算年底要补多少税
- 支持预算和储蓄率追踪，配合理财学习的各个阶段

**原则**

- 先做 MVP，只做流水记录和基础统计，能用再说
- MVP 只有一个登录用户（我），但数据结构按"家庭"设计，以后加多用户不用推倒重来
- 数据结构提前留好扩展位（拆分、标签、多级分类），界面功能可以晚点做

## 2. 数据来源

每个银行写一个 CSV 解析器，统一转成：日期、金额、描述、余额（有的话）。导入时选择账户，账户已经绑定银行，自动用对应解析器。详细格式见 `business-rules.md` R1。

### ANZ CSV（已用真实导出确认）

- 导出：Internet Banking → 账户 → Transactions → Download → 选日期范围和 CSV
- 每个账户需要分别导出
- 格式：**没有表头**，3 列：日期、金额、描述；日期 `DD/MM/YYYY`（入账日期）；金额带引号；新的在前；**没有余额列，没有交易 ID**
- 描述里的信息：
  - 卡号后四位：`VISA DEBIT PURCHASE CARD xxxx ...`，joint account 两张卡可以用来分归属人
  - 转账对方的完整账号，可以用来识别内部转账（入库前脱敏）
  - 前缀和噪音：`VISA DEBIT PURCHASE CARD xxxx`、`EFTPOS`、`ANZ INTERNET BANKING BPAY`、BPAY 账单码、支付通道前缀 `ZLR*` `SQ *` `SMP*`、反斜杠、连续空格
- Progress Saver 的格式还没确认，预计和 Access Advantage 一样

### CBA CSV（已用真实导出确认）

- 导出：NetBank → 账户 → 导出 CSV
- 格式：**没有表头**，4 列：日期、金额、描述、余额，全部带引号；金额和余额带 `+`/`-`；新的在前
- **有余额列**：可以自动检查余额是否连续，自动得出期初期末余额做对账，不用手动填
- 描述里的信息：
  - 卡号已经被银行打码：`Card xx1234`
  - 实际消费日期：`Value Date: dd/mm/yyyy`
  - 转到自己其他 CBA 账户：`Transfer from xx5678`（只有 4 位尾号）
  - PayID 转账只有人名，没有账号：`Transfer To <人名> PayID Phone ...`、`Fast Transfer From <人名> ...`
  - BPAY、贷款、直接扣款里有很长的参考号，要脱敏
  - 转账备注里的中文导出后变成下划线

### ANZ PDF 对账单（不作为导入来源）

- 有余额和期初期末余额，可以给 ANZ 账户做对账时参考
- 注意：Access Advantage 每月存入不满 $2000 会被收 $5 月费

### ANZ Plus

- 只能导出 PDF 对账单，不能导 CSV
- 主要用来存钱拿利息，所以 MVP 的做法是：
  - 转进转出在 ANZ 普通账户的流水里已经有了，按内部转账识别
  - **利息每月手动记一笔**（Income / Interest，税前），录入后直接确认
- PDF 解析放到后续功能

### 现金

- 手动录入（见 F3）

### 不考虑的方式

- Bankwest：暂时不用
- Open Banking（CDR）自动同步：接入需要认证资质，个人开发不现实

## 3. MVP 功能

### F1：账户管理

- 账户信息：银行（ANZ / ANZ Plus / CBA / 现金 / 其他）、账户名、类型（日常 / 储蓄 / 信用卡 / joint / 现金）、默认归属人
- 银行决定能不能导入 CSV：ANZ、CBA 可以；ANZ Plus、现金不行，只能手动录入
- 现金账户：我和老婆各一个
- 每个账户配置账号**尾号**（只存后几位），用于识别内部转账
- 卡号后四位映射到归属人（joint account 上两人各一张卡）

### F2：CSV 导入

- 上传 CSV，导入时选择账户，按账户所属银行解析
- **脱敏**：描述里的完整账号替换成只留后 4 位再入库，不存卡号和账号
- **清洗**：去掉前缀、支付通道前缀、反斜杠、多余空格，得到商家名。原始描述（脱敏后）和清洗后商家都保存
- **去重**：key = 账户 + 日期 + 金额 + 描述 + 同文件内序号。同一天同一家店两笔一样的消费靠序号区分，不会被当成重复
- **匹配待确认交易**：每笔银行交易先找有没有匹配的 pending 交易（见 F3），匹配上就确认那笔，不新增
- **对账校验**：检查"期初 + 本期交易合计 = 期末"，对不上说明漏导或重复导入。ANZ 可选手动填期初期末；CBA 从余额列自动得出
- **余额检查**（CBA）：相邻两行余额对不上时显示警告，不阻止导入
- **转账配对**：每次导入后对整个家庭重新配对内部转账，先导哪个账户都能对上

### F3：手动录入

- 用途：现金收支、买完东西随手记一笔刷卡消费
- 表单：日期、金额、描述、账户、分类、归属人，字段尽量少
- **这是唯一要求手机上好用的功能**：现金消费通常在外面发生，要能当场记
- 快速录入：
  - 电脑上在顶栏有"记一笔"按钮；手机上是悬浮的 + 按钮
  - 打开就聚焦金额，弹出数字键盘
  - 日期默认今天，账户默认上次用的
  - 分类按常用排序，能根据描述自动猜
- 状态：
  - 现金、ANZ Plus 这类不能导入 CSV 的账户：录入后直接是 `confirmed`
  - ANZ、CBA 账户：录入后是 `pending`，马上计入统计，等月底导入 CSV 时自动匹配确认
- 匹配规则：同账户、金额相同、日期相差 0 到 3 天，多个候选时手动选
- 导入后还没匹配上的 pending 交易提示检查（金额录错、账户选错，或其实是现金）

### F4：归属人

- 含义：**钱用在谁身上**，不是谁付的钱
- 归属人：Male（我）、Female（老婆）、Home（家庭共同部分）。以后加 Kid，加一条记录即可
- 优先级：手动指定 > 分类默认 > 卡号映射 > 账户默认值（R5）
- 分类默认：Home & utilities、Groceries、Insurance & financial 默认 Home。比如我用自己的卡在 Coles 买菜，归 Home 而不是 Male
- 没有分类默认的（咖啡、衣服、理发等）按卡号分到个人，没卡号按账户
- 改分类时，没手动改过归属人的交易会跟着重新计算
- 归属人和分类是两个独立维度
- 归属人不是登录账号，MVP 只有我一个用户

### F5：分类

- 两级分类：一级 6 个支出类 + Income（见第 7 节），二级用默认项 + 自定义
- 每个一级分类自动带一个 **Other** 二级，放不进其他二级的先归到这里
- 规则匹配：用清洗后商家名的关键词匹配（如含 `COLES` → Groceries / Supermarket），门店号不影响
- 匹配不到的归到"未分类"，在 F8 流水查询里手动选，选完可以一键存成新规则
- **内部转账**：
  - 描述里的账号尾号匹配上自己的账户 → 自动标记
  - 匹配不到时兜底：自己两个账户之间同金额、一正一负、日期相差 2 天内，标成"建议"，在 F8 确认后才算转账
  - 内部转账不计收入或支出
- **ATM 取现**（如 `NON-ANZ ATM`）：直接算一笔"现金支出"，现金花在哪不再细记
- **退款和报销**：冲减原分类，不算收入
- **储蓄和投资不算支出**：转到储蓄账户是内部转账，储蓄率单独计算
- **超市一次买很多东西**：默认整笔归一个分类。Groceries 的二级按"店的类型"理解（超市、肉店、果蔬店），在 Coles 买的水果算 Supermarket，不算 Fruit
- 混在超市账单里、**不属于 Groceries 的东西**（卫生纸、洗发水等）用 F10 拆出来

### F6：看板

- 看板就是首页，先回答"这个月钱花哪去了"，交易明细放在第二层（F8）
- **时间段选择**：本周、上周、本月（默认）、上月、本季度、今年、本财年（7 月 1 日到次年 6 月 30 日）、自定义起止日期。看板上所有数字都跟着选的时间段变
- 总收入（其中税前部分单独显示）、总支出、储蓄率
- 各分类支出金额和占比，可以看一级汇总，也可以展开二级
- 按归属人筛选或对比（Home、Male、Female）
- **汇总表**（R10.2）：按周或按月切分，按分类或归属人分组，每格是金额合计，带行合计和列合计。比如"按月 × 归属人"看每个月各人花了多少，"按周 × 分类"看每周买菜的波动
- 预计年底补税卡片（F9）
- 和上一个同长度时间段对比（如本月对上月）
- 支出最多的商家 Top N
- 趋势图：近 12 个月的收支趋势、各分类每月变化
- pending 交易计入统计，可以区分显示
- 点任意数字或分类，跳转到 F8 并带上对应的筛选条件

### F7：预算

- 给分类设月度上限（一级或二级）
- 显示当月执行进度
- 超出或接近上限时有提醒
- 可以把常用预算固定在首页顶部

### F8：流水查询

- 交易列表，默认按日期倒序
- **筛选**：时间段、账户、归属人、分类（一级或二级）、类型（收入 / 支出 / 内部转账）、状态（pending / confirmed）、是否税前、商家关键词、金额范围，条件可以组合
- 筛选结果显示**笔数和合计金额**（如"今年在 Coles 一共花了多少"）
- 列表里直接改分类、改归属人，改分类后可以一键存成规则
- 批量操作：多选后一起改分类或归属人
- 点一条看详情：原始描述（脱敏后）、商家名、来源、状态、拆分
- "未分类"的交易有快捷入口，导入后集中处理
- 详情页有"拆出一部分"按钮（F10）

### F9：税前收入和税后估算

- 背景：老婆有一部分 B2B 收入，按发票全额收款，不代扣税；银行利息也是税前的。工资进银行时已经扣过 PAYG，不用处理
- 收入拆分有"税前"标记，Contract income (B2B) 和 Interest 默认税前，单笔可以改
- 付给 ATO 的预缴税和 BAS 记在 Income / Tax (ATO) 下，负数；退税记正数。交税不算支出
- 设置页：每人每个财年填一次工资税前总额和已代扣的税（来自工资单或 myGov income statement）
- 每人每个财年估算：应纳税收入、预计总税额（按 ATO 分档 + 2% Medicare levy）、已缴、**预计年底补税**（R14）
- Home 名下的税前收入（如 joint account 利息）在两人之间平分
- 税率表按财年配置，每年手动更新
- 只是估算，不算业务开支抵扣和各种 offset，结果偏高。界面上写明以 ATO 为准

### F10：简单拆分

- 场景：超市一笔消费里有日用品、个人护理用品，属于别的一级分类或别的人
- 在交易详情里点"拆出一部分"：填金额，选分类和归属人
- 剩下的金额自动留在原来那部分（主拆分），不用手算
- 可以拆多次；删除某个拆分，金额回到主拆分
- 只在值得的时候拆（比如日用品超过 $20），平时不用管
- 规则见 R15

## 4. 后续功能（非 MVP）

- **多用户**：老婆有自己的登录账号，录入自己的账户流水，两人都能查看全部数据。登录账号关联到对应的归属人
- **录入人和通知**：每笔交易记录是谁录入的（`created_by`），和归属人分开显示；对方新增交易时收到通知
- **逐件拆分**：按小票每件商品拆分（MVP 只有 F10 简单拆分）
- **小票识别**：拍小票，用 LLM 读出商品明细，自动生成拆分（见下面"AI 功能"）。小票不产生新交易，只给已有交易补明细；匹配不到银行交易的才生成现金交易；小票合计和银行金额的差额单独记一条
- **标签**：横向标记，一笔可以多个（如 #生日、#旅行、#可抵税、#孩子）
- **现金精细记录**：取现算内部转账，现金花在哪逐笔记
- 孩子：加 Kid 归属人，花在孩子身上的钱按归属人统计，不单独设分类
- 按归属人设预算（如个人零花钱）
- 净资产追踪：手动录入 super、投资、负债，按季度记录
- 理财目标：设定目标金额和时间，追踪进度（对应学习计划阶段 8）
- 订阅检测：自动识别周期性扣款
- 应急金进度（对应学习计划阶段 2）
- 抵税支出标记：年底导出给报税用（对应学习计划阶段 3）
- 统计增强：任意两个时间段对比、超过 12 个月的长期趋势
- 导出筛选结果（CSV / Excel / PDF）
- 税务增强：业务开支抵扣、Medicare levy 低收入减免、GST 处理（如果老婆注册了 GST）
- ANZ Plus PDF 对账单解析

### AI 功能（都在 MVP 之后）

**原则**
- 解析、脱敏、去重、转账识别、统计、税后估算**不用 AI**：跟钱直接相关，必须每次结果一样、能写测试
- AI 只给建议，由我确认。确认后的结果存成规则或拆分，规则才是正本
- AI 停了或额度用完，核心功能完全不受影响
- MVP 先不做。M4 流水查询做完、真实用一两个月，看未分类有多少再决定

**功能，按优先级**

| # | 功能 | 做什么 | 发给 LLM 的内容 |
|---|---|---|---|
| 1 | 未分类的分类建议 | 导入后规则没匹配上的商家，批量问 LLM，建议二级分类和规则关键词；确认后存成规则（R13） | 只发清洗后的商家名和分类列表 |
| 2 | 小票识别 | 拍小票，读出每件商品，按分类自动拆分（F10 / R15），匹配已有的银行交易 | 小票图片（需要支持图片的模型） |
| 3 | 月度总结和问答 | "这个月比上月多花在哪"、"外食是不是越来越多" | 只发汇总后的数字，不发逐笔交易 |

**隐私**
- 不发金额、日期、账户、卡号
- PayID 转账（描述里有朋友的名字）不发
- 只选不拿免费数据训练模型的服务商（见 `tech-stack.md` 第 11 节）

## 5. 非功能需求

- **隐私和安全**：财务数据高度敏感
  - 不存完整账号、卡号，只存尾号和卡号后四位
  - 云端数据库必须有登录，所有数据按 `household_id` 隔离
  - 分享样本数据前先打码（姓名、地址、BSB、账号）
- **成本**：全部用免费服务
- **电脑优先**：主要在电脑上导入、查流水、看看板，界面按 1280px 以上宽度设计
- **手机能用**：其他页面在手机上能打开、不横向滚动就行；快速录入（F3）在手机上要顺手
- **维护**：自己一个人维护，架构不要过度设计
- **可扩展**：MVP 单用户，但不能堵死以后多人录入和查看

## 6. 设计原则

参考了 Moneon（手机记账 app）的产品取舍。界面风格另外出设计图（电脑端优先，页面清单和命名见 `design/README.md`），这里只定原则。

1. **首页只回答"钱花哪去了"**：本月总支出、分类占比、预算进度。交易列表是第二层，点进去才看
2. **从汇总到明细逐层展开**：一级分类 → 二级分类 → 具体交易
3. **录入摩擦要小**：多一步操作，坚持的人就少一批。默认值能填的都填好
4. **预算要看得见**：放在首页，每次打开都能看到，不藏在单独页面里
5. **共享时要透明**：以后两人都录入时，每笔显示是谁记的，目的是不用互相问"这笔是什么"
6. **导入优先，手动是补充**：Hearth 的核心优势是银行导入，避免了纯手动记账难以坚持的问题。手动录入只服务现金和随手记，不扩大它的比重

## 8. 平台和部署

**已确定**：Web app + 云端数据库，电脑优先，手机能用。MVP 单用户，数据结构按家庭设计。

**已排除**：

- Electron / Tauri（本地）：以后两人录入要自己做同步
- React Native / Expo：要学移动端，手机上导 CSV 不顺手；响应式 Web 已经能满足手机录入
- WPF / .NET MAUI：UI 开发体验不如 React

**已选定**：Next.js（Vercel）+ Neon Postgres + Drizzle + Better Auth + shadcn/ui，全部免费。细节见 `tech-stack.md`。

未选的方案：Supabase（免费版闲置 7 天会暂停）、.NET 后端（多一层部署，和"快速能用"不符）。

备注：

- Vercel Hobby 限个人非商业使用，家庭记账符合
- 数据量很小，免费额度的存储远远够用
- AI 功能优先用免费的 LLM API（见 `tech-stack.md` 第 11 节），不在 MVP 范围

## 9. 数据模型

完整表结构见 `schema.md`。要点：

- 银行账户表叫 `financial_account`（Better Auth 已占用 `account`）
- 分类和归属人放在 `transaction_split` 上，普通交易只有一行拆分
- `transaction` 有 `status`（pending / confirmed）、`source`（csv / manual / receipt）、`transfer_status`（none / auto / suggested / confirmed）
- `category` 有默认归属人和默认税前标记；`transaction_split` 有 `member_source`、`is_pre_tax`
- `tax_profile`：每人每财年的工资税前总额和已代扣税
- 以后加：`tag`、`transaction_tag`、`receipt`
