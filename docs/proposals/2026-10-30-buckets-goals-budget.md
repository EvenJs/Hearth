## N1：月均支出

### 要回答的问题
- 我们家平均每个月花多少钱？
- 每个分类平均每月花多少？每个人呢？
- 这个月比平均多还是少？

### 需求
- 看板加一张"月均支出"卡片：近 N 个**完整月**的平均（当月没过完，不算进去）
- 能按一级分类、二级分类、归属人看月均
- 本月和月均对比：如"本月 Groceries $820，月均 $760，+8%"
- 口径和 R10 一致：内部转账、储蓄转出、交税不算支出；退款冲减；pending 计入
- 数据不满 N 个月时，用已有的完整月算，并写明"基于 X 个月"

### 口径（2026-10-30 定）

**月均 = 近 12 个完整月、排除一次性开销后的平均数**

- 窗口默认 12 个完整月，当月不算。数据不满 12 个月时用已有的完整月，写明"基于 X 个月"
  - 为什么是 12：rego、车险、council rates 这类一年一次的账单是正常开销，不算一次性。12 个月里每样正好出现一次，平均下来就是"每月摊多少"。6 个月的窗口里有时包含、有时不包含，月均会忽高忽低
  - 另外显示"近 3 个月平均"，看最近的趋势
- 用平均数，不用中位数：一次性开销排除以后，剩下的平均数已经稳了；而且各分类的月均加起来正好等于总月均，中位数加不起来
- **一次性开销手动标记**（2026-10-30 确认用勾选框，不做成分类）：拆分上加"一次性"勾选（拆分级，因为一笔超市账单里可能只有一部分是一次性的，比如顺手买的电器）
  - 例子：家具家电、装修、旅行、大额礼物
  - 不算一次性：一年一次的账单（rego、保险、council rates）
  - 为什么不做成分类：一次性和分类是两个独立维度（和归属人一样）。放进"一次性"分类，看板上就只剩"一次性 $3000"，看不出是家具还是旅行；Furniture 的预算也统计不到它
  - 提示：单笔支出超过某个金额（如 $500，可以改）且没标过，在 F8 提示"是不是一次性？"，只提示不自动标
- 看板上本月、本期的总支出照常包括一次性开销（钱确实花了），另外显示"其中一次性 $X"。只有月均和用到月均的地方（应急金、预算建议）排除

**必要支出 = 排除一次性开销以后的全部支出**

- 不再按分类打"必要 / 非必要"的标，就是上面的月均
- 应急金目标 = 月均 × 6（月数可以改）
- 以后觉得应急金目标偏高（外食、娱乐也算进去了），再考虑按分类排除

## N2：账户用途（bucket）和余额

### 要回答的问题
- 每个账户里现在有多少钱？
- 钱是不是放在对的地方：日常账户别放太多，应急金、储蓄放在高息账户
- 应急金、储蓄、目标各有多少？

### N2.1 账户余额（地基）

现在各账户能不能拿到余额：

| 账户 | 余额来源 |
|---|---|
| CBA | CSV 每行有余额，自动有 |
| ANZ（Access Advantage、Progress Saver、Joint） | CSV 没有；PDF 对账单有期末余额（M6.6） |
| ANZ Plus | 只有 PDF，M7.5 之前只能手动 |
| 现金 | 手动 |

需求：
- 每个账户显示**当前余额**和"截至哪天"
- 算法思路：最近一个可信的余额锚点（CBA 最新一行 / 最近一份 PDF 期末 / 手动填的）+ 锚点之后的交易合计
- 手动校准：可以随时填"今天网银显示多少"，和计算值对不上时提示（可能漏导）
- 账户页加一个"总资产"（所有账户余额合计，不含 super、投资，那些是后面的净资产追踪）

### N2.2 账户用途

给每个账户设一个用途：

| 用途 | 例子 | 说明 |
|---|---|---|
| 日常 everyday | ANZ Access Advantage、CBA 日常 | 工资进来、日常消费 |
| 账单 bills | Joint | 房贷、物业、水电这些固定账单 |
| 应急金 emergency | 某个储蓄账户 | 只在应急时动 |
| 储蓄 / 高息 savings | ANZ Plus、Progress Saver | 存钱拿利息 |
| 目标 goal | 某个专门的账户 | 挂到 N3 的目标上 |

- 用途和现有的 `type` 分开：`type` 是银行账户类型，用途是"这笔钱拿来干嘛"
- 账户页按用途分组显示余额
- 可选：每个用途显示利息收入（Income / Interest 按账户汇总），看高息账户实际赚了多少

### N2.3 虚拟 bucket（2026-10-30 定：不做手动拆分；多个目标共用一个账户时按优先级填，见 prd F14）

一个账户里的钱分成几块，比如 ANZ Plus 里 $20k = 应急金 $15k + 旅行 $5k。

- 好处：不用为每个目的开一个银行账户
- 代价：bucket 之间的划转是"虚拟"的，银行流水里没有，要手动记；一个人维护会多出一类要对的数
- 建议：**先只做 N2.2（一个账户一个用途）**。真需要拆时，开银行子账户比在 app 里拆更简单（ANZ Plus 本身支持多个储蓄账户）。见第 6 节问题 1

### N2.4 关联账户和 bonus interest（2026-10-30 补）

澳洲银行的常见做法：saver 账户 link 到一个 everyday 账户，saver 有高息、everyday 没有利息；bonus interest 要每个月满足条件才拿得到，没满足当月只有很低的基础利率。钱在两个账户之间进出，都是内部转账（R6）。

需求：
- saver 账户可以设"关联的 everyday 账户"
- 每个 saver 账户可以配置 bonus 条件，**条件自己按银行的说明填**，app 不内置哪家银行是什么条件（会变）
- 常见的条件类型（先支持这几种，开始前再确认）：

| 条件类型 | 例子 | 怎么用流水判断 |
|---|---|---|
| 当月存入至少 $X | 每月存入 $10 以上 | saver 当月流入合计 |
| 当月不取款 | 当月没有转出 | saver 当月没有流出（利息、手续费不算） |
| 当月余额增长 | 月末余额比上月末高 | 需要 N2.1 余额 |
| 关联账户当月存入至少 $X | everyday 每月存入 $2000 | 关联 everyday 当月流入合计（不算从 saver 转回来的） |
| 关联账户当月刷卡 N 笔 | everyday 每月 5 笔消费 | 关联 everyday 当月支出笔数 |

- 录入方式（2026-10-30 定）：用户自己录。选条件类型、填金额或笔数，app 每月自动判断
  - 兜底"其他"：上面类型放不下的条件写一句文字，app 判断不了，每月自己勾"满足了没有"
- 每个月显示每个条件"已满足 / 还差多少 / 已经失败"，比如"本月还没存入，还差 $10"、"3 号从 Progress Saver 转出 $200，本月 bonus 没了"
- 月底前几天（如最后 5 天）条件还没满足时，看板上提醒
- 历史：每个月拿没拿到 bonus 一目了然，配合 Income / Interest 看实际赚了多少利息
- 想从 saver 取钱时，这个提醒也能帮忙判断"这个月取还是下个月初再取"

注意：
- 判断靠导入的流水，**没导到最新就不准**，提醒上写明"数据截至哪天"
- ANZ Access Advantage 每月存入不满 $2000 收 $5 月费（prd 第 2 节），也是同一类"每月条件"，可以用同一套检查，只是结果是"收费"而不是"拿 bonus"

### N2.5 为了满足条件来回转钱（2026-10-30 补）

打算：每月把 $2000 在自己不同银行的账户之间转一圈，满足 Access Advantage 的存入要求。

- 统计不受影响：两边都是自己的账户，按 R6 是内部转账，不计收支
- **ANZ 官网没写从自己其他 ANZ 账户转进来算不算"存入"**，只说当月最后一个工作日前存入 $2000 以上。先问 ANZ 或者试一个月
- 所以条件要能选"哪些存入算数"：任何存入 / 排除同一家银行的账户 / 排除关联 saver 转回来的
- 自动校验：某个月 app 判断"已满足"，但流水里还是出现了 $5 月费（Bank fees），就提示"条件判断可能不对"，用真实结果反过来校正配置
- 转账识别：
  - 描述里有账号尾号的（ANZ 转出、CBA 的 `Transfer from xx1234`），配好尾号就自动认（R6.1）
  - 走 PayID 只有人名的，会落到 R6.3 兜底"建议"，每月要手动确认两次。可以考虑加一条"固定的周期性转账自动确认"，开始前再定
- 月底前提醒："本月 Access Advantage 已存入 $X，还差 $Y"
- 中转用的是别的银行（BOQ、Westpac 等，2026-10-30）。这些账户**不用做解析器**，按 ANZ Plus 现在的做法：
  - 在 app 里建账户，`bank = other`，填账号尾号
  - ANZ 那一侧的转出、转入靠尾号被 R6.1 认成内部转账，另一侧没有流水，配不上对也没关系（和 ANZ Plus 一样）
  - 不建账户的话，ANZ 转出会被当成支出、转回会被当成收入，月度收支各多 $2000，储蓄率也会偏
  - 余额：当天转出当天转回，月底应该是 0；钱放过月底的话，用 N2.1 手动填余额
  - 以后哪个账户要长期放钱（比如开了高息 saver），再考虑给那家银行写解析器，先拿真实导出看格式

## N3：目标（含应急金）

### 要回答的问题
- 应急金够不够？够几个月？
- 每个目标（买车、旅行、换房首付）存到多少了，按现在的速度什么时候能达成？

### 需求
- 目标：名字、目标金额、目标日期（可选）、挂的账户（一个或几个）
- 进度 = 挂的账户当前余额 ÷ 目标金额（依赖 N2.1）
- 预计达成：按近 3 个月这些账户的净流入估算；有目标日期时显示"每月还要存多少才能按时达成"
- **应急金是一个特殊目标**：
  - 目标金额 = 月均支出（N1，已排除一次性）× 月数（默认 6，可以改）
  - 显示"当前能撑 X.X 个月"
  - 月均支出变了，目标金额跟着变
- 看板放一张目标进度卡片，和预算一样可以固定到首页
