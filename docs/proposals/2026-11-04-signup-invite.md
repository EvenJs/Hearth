## 1. 已经定的（2026-11-04）

- **一直开放注册，靠邀请码挡人**。没有有效邀请码，注册接口直接报错。不单独做注册开关
- **邀请码两种用途**
  - `join`：加入发邀请的人所在的家庭（比如老婆、以后的孩子）
  - `new_household`：注册后新建一个自己的家庭（比如朋友）
- **新建家庭时自动建**：预置分类和预置规则（照 `seed-categories.md`，复用 `seedHousehold`），归属人只建注册的这个人 + 一个"共同"（`shared`）。账户让他自己建
- **小票 LLM 识别所有家庭都能用，每个家庭每月有限额**。超了显示"本月识别次数用完了"，还能粘贴文字或手动填（R20.1 本来就支持）
- **要做忘记密码和邮箱验证**。发邮件用 Gmail SMTP + `nodemailer`，见第 3 节
- **只有站长（我）能发 `new_household` 的码**，用环境变量 `ADMIN_EMAILS` 判断。普通用户只能发 `join`（2026-11-05）
- **`join` 的码发码时就指定归属人**，注册的人不用选（2026-11-05）
- **没验证邮箱不能登录**（2026-11-05）
- **小票每月限额 50 次**（2026-11-05）
- **邀请码 3 天过期，只能用一次**（2026-11-05）
- **退出家庭、删账号这次不做**（2026-11-05）

## 2. 需求

### 2.1 生成邀请码
- 设置页加"邀请"：选用途（加入我们家 / 新建家庭，后者只有站长看得到），`join` 要选一个归属人，生成一个码，比如 `HX7K-29QD`，能复制
- 码默认**用一次就作废**，**3 天过期**
- 能看到自己发过的码：状态（没用 / 已用 / 过期 / 撤销）、谁用了、什么时候用的
- 没用的码可以撤销

### 2.2 注册
- 登录页加"注册"入口：邮箱、名字、密码、邀请码
- 邀请码当场校验：不存在、已用、过期、撤销都提示，不建账号
- 校验通过，**同一个事务里**：建用户 → 按用途建 `household_user`（`join` 进发码人的家庭；`new_household` 先建家庭再 seed）→ 把码标成已用
- 两个人同时用同一个码：只能成功一个
- `join` 进来的人，`household_user.member_id` 用码上指定的归属人；`new_household` 用新建的那个归属人

### 2.3 邮箱验证和忘记密码
- 注册后发验证邮件，**没验证不能登录**，登录页能重发验证邮件
- 登录页"忘记密码"：发重置链接
- 登录后设置页能改密码、改名字
- Better Auth 自带这些流程，只需要接一个发邮件的函数

### 2.4 小票识别限额
- 每个家庭每月 50 次 LLM 识别（放环境变量 `RECEIPT_LLM_MONTHLY_LIMIT`，默认 50）
- **按调用 LLM 的次数算**，不按存下来的小票算（识别了没保存也算一次）
- 按 `Australia/Melbourne` 的自然月重置
- 小票页显示"本月还能识别 X 次"

## 3. 发邮件服务（2026-11-05 定：Gmail SMTP + nodemailer）

Better Auth 只要一个 `sendEmail(to, subject, html)` 函数，换服务商只改这一个地方。候选：

| 服务 | 免费额度 | 要做的 |
|---|---|---|
| Resend | 每月 3000 封，每天 100 封 | 要验证一个自己的域名（加 DNS 记录） |
| Brevo | 每天 300 封 | 可以不用自己的域名，但容易进垃圾箱 |
| Gmail SMTP + nodemailer | 每天几百封 | 不用域名，要开应用专用密码 |

现在用的是 `*.vercel.app`，没有自己的域名（2026-11-05）。所以：

- Resend 不验证域名只能发给自己的邮箱，**用不了**，除非买个域名（一年大概 $15，不算免费）
- Brevo 能只验证一个发件邮箱，但用 Gmail 地址当发件人会被 DMARC 拦，大概率进垃圾箱
- **定了：Gmail SMTP + `nodemailer`**：建一个专门的 Gmail 账号，开两步验证，生成应用专用密码，放 `SMTP_USER`、`SMTP_PASS`。每天几百封，两三个家庭用不完
