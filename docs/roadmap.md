# Hearth 开发路线图

> 一次只做一个里程碑。每个里程碑完成的标准：验收清单全部打勾、测试全部通过、自己在手机和电脑上各点一遍、commit 并部署。
> 规则编号（R1 等）见 `business-rules.md`，功能编号（F1 等）见 `prd.md`。
> 每个里程碑开始前拆成任务清单，放在 `docs/tasks/`（目前已拆 M0、M1、M2）。

---

## M0：项目骨架和上线

**做什么**

- `create-next-app`（TypeScript、App Router、Tailwind、ESLint），pnpm
- 装 shadcn/ui、Drizzle、Neon 驱动、Better Auth、Vitest、Prettier
- Neon 建 dev 和 prod 两个 branch
- Better Auth：邮箱密码登录，关闭公开注册，写一个脚本手动创建用户
- 一个登录页 + 一个登录后才能看的空首页
- 推到 GitHub，连上 Vercel，配好环境变量

**验收**

- [ ] 线上地址能打开，未登录跳到登录页
- [ ] 用脚本创建的账号能登录、退出
- [ ] 注册接口不可用
- [ ] `pnpm test` 能跑（哪怕只有一个示例测试）
- [ ] `.env.local` 不在 git 里，有 `.env.example`

---

## M1：数据库和种子数据

**做什么**

- 按 `schema.md` 写 `src/db/schema.ts`，生成迁移并检查 SQL
- seed 脚本：household、3 个 member、`seed-categories.md` 的分类和规则、把当前用户加进 `household_user`
- 数据访问层的基础：拿当前用户的 `household_id` 的函数，所有查询都经过它
- 账户管理页（F1）：增删改账户、卡号映射

**验收**

- [ ] 迁移在 dev 和 prod 都跑通
- [ ] seed 可以重复跑不报错（幂等）
- [ ] 能建出 fixtures/README 里的 3 个账户和 2 张卡
- [ ] `number_suffix` 只接受 4 到 6 位数字

---

## M2：ANZ / CBA 解析器和规则（纯函数）

**这个里程碑不碰数据库和页面。** 先写测试，再写实现。

**做什么**

- `src/lib/import/anz.ts`：R1A
- `src/lib/import/cba.ts`：R1B，含余额连续性检查和期初期末推算
- `src/lib/rules/`：R2 提取脱敏、R3 清洗、R4 key 生成、R7 分类、R5 归属人（含 R5.1 重算）、R6.1 转账识别、R8.2 pending 候选查找、R10 统计计算、R10.2 按周按月汇总、R13 关键词建议
- `src/lib/tax/`：R14 税率表和税后估算
- 测试用 `fixtures/` 的文件，期望值照 `fixtures/README.md`

**验收**

- [ ] fixtures/README 里 `joint-2026-09.csv` 的 19 行期望全部有测试并通过
- [ ] `cba/female-2026-09.csv` 的 20 行期望全部通过；`broken-balance.csv` 只警告不失败
- [ ] R10.2 的按周例子、R14.5 的 A 到 D 四个场景都有测试
- [ ] 两个 invalid 文件都整体失败，错误带行号
- [ ] CRLF 和 LF 两个版本解析结果相同
- [ ] 测试检查输出里没有任何 8 位以上连续数字
- [ ] 用自己真实的 ANZ 和 CBA 导出本地跑一下（不提交），没有报错

## M3：导入流程

**做什么**

- 导入页：选账户、上传 CSV、ANZ 可选填期初期末余额（CBA 自动）；不能导入的账户（ANZ Plus、现金）不出现在选项里
- R12 完整流程，一个事务
- R6.2 配对、R6.3 兜底建议
- R9 对账
- 导入结果页：新增、跳过、确认的 pending、未分类数、待检查 pending、对账结果、余额警告
- 导入历史列表，可以撤销（R12.1）

**验收**

- [ ] 按 fixtures/README 的顺序导入 joint → overlap → me → cba，数据库结果和期望一致（包括 joint #11 和 CBA #10 跨银行配对）
- [ ] 中途故意抛错，数据库没有残留（事务回滚）
- [ ] 撤销一次导入后，再导同一个文件，结果和第一次一样
- [ ] 用真实的半年 ANZ 流水导入，期初期末余额和 PDF 对账单对得上
- [ ] 用真实的 CBA 流水导入，自动对账通过、没有余额警告

## M4：流水查询（F8）

**做什么**

- 交易列表，组合筛选，笔数和合计
- 行内改分类、改归属人（写 `category_source = manual`）
- 改分类后"存成规则"（R13），可选择应用到未分类的交易（R7.2）
- 批量修改
- 交易详情
- "未分类"快捷入口
- suggested 转账的确认和拒绝
- 简单拆分（F10、R15）：详情页"拆出一部分"，删除拆分

**验收**

- [ ] 筛选"今年 + 商家含 COLES"，合计正确
- [ ] 存规则后应用，只改了未分类和 `rule` 来源的交易，`manual` 的没动
- [ ] 手机上列表能用，筛选不挤
- [ ] fixtures/README 的拆分用例结果一致

---

## M5：看板（F6）

**做什么**

- 首页看板：时间段选择（R10.1）、收入（含税前部分）、支出、储蓄率、分类占比（一级可展开二级）、归属人筛选、对比上期、Top 商家、未分类提示
- 汇总表（R10.2）：按周 / 按月 × 分类 / 归属人
- 近 12 个月趋势图
- 点数字跳到 F8 并带上筛选

**验收**

- [ ] 只导入 `joint-2026-09.csv` 时，2026 年 9 月数字和 fixtures/README 的统计表一致
- [ ] 本财年在 10 月显示 7 月 1 日起的数据
- [ ] 内部转账不出现在收支里
- [ ] 汇总表按周的结果和 R10.2 的例子一致

---

## M6：手动录入和 pending（F3）

**做什么**

- 悬浮 + 按钮，快速录入表单（聚焦金额、数字键盘、默认今天和上次账户、常用分类在前、按描述猜分类）
- cash 账户直接 confirmed，其他 pending（R8.1）
- 导入时匹配 pending（R8.2、R8.3），导入结果里提示（R8.4）
- 手动录入的交易可以编辑、删除

**验收**

- [ ] fixtures/README 的 P1 到 P6 用例全部符合期望
- [ ] 手机上从点 + 到保存一笔，不超过 10 秒

---

## M7：预算和税后估算（F7、F9）

**做什么**

- 给一级或二级分类设月度上限、提醒百分比
- 预算进度（R11），黄色、红色提醒
- 固定到首页顶部
- 设置页：每人每财年填工资税前总额和已代扣税（`tax_profile`）
- 看板上每人一张税务卡片（R14.6）

**验收**

- [ ] 一级分类预算统计了所有二级
- [ ] 退款能让进度回落
- [ ] 用 `fixtures/cba/female-2026-09.csv` 和 R14.5 场景 A 的 tax_profile，卡片数字正确
- [ ] 卡片上写明"估算，以 ATO 为准"

## M8：收尾

**做什么**

- 确认 ANZ Progress Saver 的 CSV 格式，不一样的话补解析规则和 fixtures
- 现金账户（我、老婆各一个）、ANZ Plus 每月手动记利息的流程顺手
- 空状态、加载状态、错误提示
- README：本地启动、部署、创建用户、备份数据（Neon 导出）

**验收**

- [ ] 所有账户的 9 月流水导入后，未分类低于 15%
- [ ] 跑一整个月真实使用，没有要改数据库的问题

## MVP 之后

按需求文档第 4 节的后续功能，建议顺序：

1. 拆分交易界面（数据结构已支持）
2. 订阅检测
3. 给老婆开账号（多用户、录入人）
4. 标签
5. 小票识别、AI 总结
