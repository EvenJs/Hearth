# R25. 目标和应急金（F14，2026-11-04 新增，M11）

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。
> 用例见 [`fixtures/cases/16-goals.md`](../../fixtures/cases/16-goals.md)。

可以建多个目标（存着的 / 要花掉的，一次或每年重复）。挂了账户的目标按优先级用账户余额（R23.2）填进度；算每月要存、预计达成、存不存得过来；应急金的金额按月均（R22）自动算。要花掉的目标买东西时把交易挂上去，看计划和实际。

- **只存目标本身和拆分挂的目标**（`transaction_split.goal_id`）。进度、每月要存、预计达成、应急金金额、存不存得过来**每次实时算，不存**（和 R23.3 差额、R24 条件状态一样）
- 除了挂目标时自动勾一次性（R25.7），不改交易的分类、归属人、转账状态。看板、F8、税务、余额、预算进度的数字都不变；月均只因为新勾的一次性而变（F11 本来的意思）
- 目标页、首页目标卡片、预算总览那一行**都不跟**看板的时间段和归属人筛选，固定按今天、全家
- 月份按 Melbourne 自然月，日期是 `YYYY-MM-DD` 字符串。"今天"按 Melbourne，纯函数把今天当参数传进来，不自己取
- 下面"本月"指今天所在的月，"月份差"指 `(年₁ × 12 + 月₁) − (年₂ × 12 + 月₂)`，只看年月，不看几号

## R25.1 目标的字段和校验

| 字段 | 说明 |
| --- | --- |
| 名字 | 必填。去首尾空格、多个空格合成一个，最长 50 字符。同家庭 `active` 的目标里不区分大小写不能重复（`done` 的不算） |
| 类型 | `keep` 存着的（应急金、首付）/ `spend` 要花掉的（包、旅行、rego） |
| 重复 | `once` / `yearly`。只有 `spend` 能选 `yearly` |
| 目标金额 | 分，> 0。应急金不填，自动算（R25.6） |
| 目标日期 | 可选，不限制早于今天（过了就显示过期，R25.2）。`yearly` 必填 |
| 挂的账户 | 可选，最多一个。只能选本家庭、没归档、不是现金的账户 |
| 优先级 | 整数，全家一个顺序，就是 `/goals` 列表的顺序。新建的排最后：本家庭所有目标（含 `done`）的最大优先级 + 1，第一个是 1 |
| 应急金 | 布尔 + 月数。月数是 1 到 24 的整数，默认 6。一个家庭最多一个应急金目标 |
| 固定到首页 | 布尔，默认不固定 |
| 状态 | `active` / `done`。`done` 记 `done_at` |

**应急金**：类型固定 `keep`、重复固定 `once`，不填目标金额。**永远排第 1**（2026-11-04 定）：同一账户里先填它（R25.3），优先级存 0，不显示、不能上下移动。不能标 `done`（R25.9）。

**保存时的校验**，按顺序，第一条不过就报错、不保存：

| # | 情况 | 错误 |
| --- | --- | --- |
| 1 | 名字是空的（去空格以后） | 请填名字 |
| 2 | 名字超过 50 字符 | 名字最多 50 个字 |
| 3 | 和别的 `active` 目标重名（不区分大小写，自己不算） | 已有同名的目标 |
| 4 | 不是应急金，目标金额没填或 ≤ 0 | 目标金额要大于 0 |
| 5 | `keep` 选了 `yearly` | 只有要花掉的目标能每年重复 |
| 6 | `yearly` 没填目标日期 | 每年重复的目标要填日期 |
| 7 | 应急金，月数不是 1 到 24 的整数 | 月数是 1 到 24 |
| 8 | 新建应急金，本家庭已经有一个 | 已经有应急金目标了 |
| 9 | 账户不存在或不是本家庭的 | 找不到这个账户（不说是别的家庭的） |
| 10 | 账户已归档 | 不能挂已归档的账户 |
| 11 | 账户是现金账户（`bank = cash`） | 不能挂现金账户 |

- 第 9 到 11 条**只在挂的账户改变时**校验（同 R23.4）。没改的不重新校验，所以已经挂着、后来归档了的账户不会让保存失败
- 设成"不挂账户"（`null`）不校验
- 表单的账户下拉里去掉已归档的、现金账户
- 一个目标只挂一个账户（prd F14），不做"一个或几个"

**账户后来归档了**：目标还在，显示"账户已归档"，没有进度（R25.3），不估预计达成，每月要存照算（还差 = 目标金额）。

## R25.2 每月要存

只算 `active`、有目标日期的目标。`done` 的不算。

```
还差     = 目标金额 − 已填进度（R25.3）；没有进度的目标，还差 = 目标金额
月数     = max(1, 目标日期的月份 − 本月)
每月要存 = ceil(还差 ÷ 月数)，向上取整到分（宁可多存 1 分）
```

- **目标月当月不算**，本月算（2026-11-03 定）：今天 2026-11-03，目标 2027-03-15 → 11、12、1、2 月 = 4 个月
- 目标月就是本月（日期还没过）→ 月数按 1 算
- 没有进度的目标：没挂账户、账户没锚点、账户已归档、应急金算不出金额（R25.6）
- 已经达成（还差 ≤ 0）→ 每月要存 = 0，显示"已存够"。0 也算进合计（不影响结果）
- **已过期**：目标日期 < 今天（2026-11-04 定），而且还没达成 → 显示"已过期，还差 $X"，提示"日期往后推"。不算每月要存，**不进合计**。目标日期 = 今天不算过期
- 已过期但已经达成 → 照"已经达成"，不显示过期
- 没有目标日期 → 不算每月要存，不进合计，显示"没有日期"
- 应急金没有目标金额（R25.6 算不出来）→ 不算每月要存，不进合计

**每月要存合计** = 所有 `active`、有日期、没过期、算得出每月要存的目标的每月要存相加。R25.5、R25.10 用的都是这个数。

用整数算：`ceil(a ÷ m)` = `floor((a + m − 1) ÷ m)`（a > 0），不要用浮点数。

## R25.3 按优先级填进度

进度用挂的账户的**可用余额**（R23.2，和 R23.5 合计用的一样）。每个账户分开填：

1. 拿出挂这个账户的 `active` 目标。`done` 的不参与
2. 排序：应急金第 1；其他按优先级从小到大
3. 剩下的 = 账户可用余额。依次给每个目标填 `min(max(剩下的, 0), 目标金额)`，剩下的减掉填的
4. 应急金算不出目标金额（R25.6）→ 这个目标不占钱，进度显示"还没有月均"，后面的照填（2026-11-03 定）

- 余额是 0 或负数（信用卡）→ 这个账户上全部 0
- 已经达成的 `keep` 目标**继续占着钱**（钱一直放着）。已经达成的 `spend` 目标也一样，要点"完成"才退出
- `done` 的不参与，所以买完一个、点了完成，后面的自动往前顶（买东西花掉的钱让余额也少了，看最后的结果）
- 账户没锚点（R23.1）→ 这个账户上的目标都显示"账户还没有余额"，没有进度
- 账户已归档 → 目标显示"账户已归档"，没有进度（归档的账户不算余额，R23.2）
- 没挂账户 → 没有进度，只显示每月要存
- 余额多出来的部分不分给任何目标，也不显示

例子（prd F14）：储蓄账户可用余额 $7000，1. 包 $5000 → 已存 $5000，已存够；2. 旅行 $4000 → 已存 $2000，还差 $2000。

## R25.4 预计达成

只给**挂了账户、账户有锚点、没归档、还没达成**的 `active` 目标估。没挂账户的不估，只显示每月要存。

**账户月净流入**：

- 这个账户近 3 个**完整月**全部交易（任何分类、含转账、含 pending）的 `amount_cents` 合计 Σ，月数 n
- 窗口照 R22.5 的近 3 个月，起点用**这个账户**最早一笔交易（任何分类、任何状态）的月份。n = min(3, 起点月到上个月的月数)
- n = 0（账户没有交易，或者最早一笔就在本月）→ "数据不够，估不出来"
- Σ ≤ 0 → "按现在的速度达不到"

**第 k 个目标**（同一账户里 R25.3 的顺序，k 从 1 开始）要等前面 1 到 k 都填满：

```
需要     = Σ(第 1 到第 k 个目标的目标金额) − 账户可用余额
月数     = ceil(需要 × n ÷ Σ)
预计达成 = 本月 + 月数（显示到月，如"预计 2027-05"）
```

- 不占钱的应急金（R25.3 第 4 步）不算进 Σ(目标金额)
- 月数用整数算 `ceil(需要 × n ÷ Σ)`，**不要**先把月净流入取整再除
- 有目标日期，预计达成的月份 > 目标日期的月份 → 标红"比目标晚 N 个月"，N = 两个月份的月份差。同一个月不算晚
- 没有日期 → 只显示预计哪个月，不比较

## R25.5 存不存得过来

```
每月要存合计   = R25.2 的合计
实际每月存下   = 近 3 个完整月的 Σ(收入 − 支出) ÷ n
```

- 收入、支出口径同 R10（全家、按交易 `date` 归月、退款冲减、pending 计入、转账和未分类不算）。不跟看板筛选
- **支出排除挂了目标的拆分**（`goal_id` 不为空，退款也一样）：那是目标的钱花掉了，不算"没存下"（2026-11-03 定）。一次性但没挂目标的拆分照算
- 窗口和起点照 R22.5 的近 3 个月（起点是本家庭最早一笔交易的月份）。n = 0 → 显示"还没有完整月的数据"，不比较、不提示
- 除法四舍五入到分，按绝对值（R22.7 第 1 步、R10.4：−500.5 → −501）
- 税前收入会让实际偏高（R10 已知局限），提示旁边不另外说明

**提示**：每月要存合计 > 0，而且（合计 > 实际，或者实际 ≤ 0）→ `/goals` 顶部显示"目标每月要存 $X，近 3 个月平均只存下 $Y，目标太多，或者日期往后推"。

- 合计 = 实际不提示
- 合计 = 0（没有要按月存的目标）不提示

## R25.6 应急金

```
目标金额   = 近 12 个月总月均 × 月数
能撑几个月 = floor(已填进度 × 10 ÷ 近 12 个月总月均) ÷ 10
```

- 总月均是 R22.7 第 1 步的值（全家、已排除一次性、四舍五入到分）。**不跟**看板的归属人筛选
- 月均变了（补导了流水、勾了一次性、过了一个月），目标金额跟着变
- 月数是目标上存的（R25.1），改了月数，目标金额跟着变
- **算不出来**：没有完整月（R22.5 n = 0），或者月均 ≤ 0 → 目标金额显示"还没有月均"，不占钱（R25.3），不算每月要存，能撑几个月显示"—"
- 能撑几个月**向下取整到 0.1**："能撑 3.4 个月"。用整数算，不要用浮点数四舍五入
- 能撑几个月看的是已填进度，不是账户余额：月数设 3、已经存够，就是"能撑 3.0 个月"
- 没挂账户 → 只显示目标金额，不显示进度和能撑几个月
- 不能标 `done`（存着的目标不会结束）。可以删除（应急金不能挂交易，R25.7）

## R25.7 挂交易（要花掉的目标）

挂在**拆分**上（`transaction_split.goal_id`），因为一次性也在拆分上。

- **只有支出口径的拆分能挂**（同 R22.1：kind = `expense`，加上现金支出、银行费用）。其他拆分不显示选择框
- 只能挂 `active` 的 `spend` 目标。`keep` 目标（含应急金）、`done` 的目标不出现在选择里
- 一个拆分最多挂一个目标；一个目标可以挂多笔（旅行：机票、酒店）
- 交易可以来自任何账户，和目标挂的账户无关（存在 saver，用信用卡买）
- 退款（正数的支出拆分）也能挂，冲减实际
- 在交易详情上每个支出拆分一个"挂到目标"下拉（shadcn `Select`），第一项"不挂"。拆分对话框（R15.2）里不提供
- 不做批量挂

**挂上时自动把这个拆分的 `is_one_off` 设成 `true`**（不管原来是 `null` 还是 `false`），旁边提示"已标成一次性"。取消挂（改成"不挂"）**不动** `is_one_off`（2026-11-03 定）。直接从目标 A 改挂目标 B 也算挂上，同样设 `true`。

- 所以挂目标会让月均变（R22.6 排除一次性）。只有挂的拆分在完整月里时才看得出来；本月的拆分不在月均窗口里

**计划和实际**：

```
实际 = −Σ 挂在这个目标上的拆分的 amount_cents（支出是负数，翻成正数；退款冲减）
差   = 实际 − 计划（计划 = 目标金额）
```

- 显示"计划 $5000，实际 $5200，多了 $200"；差 < 0 显示"少了 $X"；差 = 0 显示"刚好"
- 挂了几笔：挂在这个目标上的拆分个数
- 实际和进度无关：进度看账户余额（R25.3），实际看挂的交易
- **挂交易不自动完成**。`active` 的 `spend` 目标挂了至少一笔以后，目标上提示"买完了吗？"，点"完成"才变 `done`（R25.9）
- `done` 的目标：挂上的交易还能看，不能再挂新的；可以取消挂（改正挂错的），实际跟着变

**保存时的校验**（Server Action 里，按顺序）：

| # | 情况 | 错误 |
| --- | --- | --- |
| 1 | 拆分不存在或不是本家庭的 | 找不到这笔交易 |
| 2 | 拆分不是支出口径 | 只有支出能挂到目标 |
| 3 | 目标不存在或不是本家庭的 | 找不到这个目标 |
| 4 | 目标不是 `spend` | 只能挂到要花掉的目标 |
| 5 | 目标是 `done` | 目标已经完成，不能再挂 |

改成"不挂"只校验第 1 条。

## R25.8 各种操作后 `goal_id` 怎么变

总原则和 R22.2 一样：**拆分的分类改到非支出口径时，`goal_id` 清成 `null`；其他情况不动。** 唯一例外是小票保存。

| 操作 | `goal_id` |
| --- | --- |
| 导入、手动录入（R17）新建主拆分 | `null` |
| 拆出一部分（R15.2） | 新拆分 `null`（拆分对话框不提供挂目标）；主拆分不变 |
| 改非主拆分金额（R15.3） | 两边都不变 |
| 删除非主拆分（R15.3） | 跟着没了；主拆分不变 |
| 改分类（R16.4）、批量改分类、规则重新应用（R7.2）、R6.4 重新识别 | 新分类还是支出口径 → 不变；改成收入、内部转账、未分类 → `null` |
| 改归属人、改备注、R17.5 改金额或日期 | 不变 |
| pending 确认（R8.3） | 保留；R8.3 例外里主拆分改成内部转账的 → `null` |
| 确认转账建议（R6.3） | 分类变内部转账 → `null` |
| 归档分类（R19.4） | 不变 |
| 小票保存（R20.3） | 保存后**所有拆分都是 `null`**。保存前有任何一个拆分挂了目标，保存后提示"挂的目标已清掉，需要的话重新挂"（和一次性的提示 R22.2 一起出现时两句都显示） |
| 撤销导入（R12.1）、删除交易（R17.5） | 拆分删掉，跟着没了 |

- `goal_id` 清成 `null` 时 `is_one_off` 照 R22.2 自己变，不另外处理（改到非支出口径时两个都清；小票保存时两个都清）
- 写拆分的代码（`writeSplits` 的 `fields()`、导入、手动录入、pending 确认）只写列出的字段，**不要**在更新分类时顺手把 `goal_id` 写成默认值
- 撤销导入、删除交易**不检查**拆分挂没挂目标，照删。目标的实际跟着变

## R25.9 完成、撤销完成、删除、每年重复

**完成**（`active` → `done`）：

- 不是应急金的 `active` 目标都能点"完成"，`keep`（如首付）也可以。不要求挂了交易
- `once`：变 `done`，`done_at` = 现在。从 R25.3 的填进度里退出，同一账户后面的往前顶。进"已完成"列表，留着计划和实际
- `yearly`：这一期变 `done`，**同时**建下一期（一次事务）：
  - 照抄：名字、类型、重复、目标金额、挂的账户、优先级、固定到首页
  - 目标日期 + 1 年；2 月 29 日 → 下一年 2 月 28 日
  - 状态 `active`，`prev_goal_id` = 这一期
  - 不检查挂的账户现在是否归档（照抄，显示"账户已归档"）
- 下一期和这一期同名、同优先级不冲突：重名只看 `active`，这一期已经 `done`

**撤销完成**（`done` → `active`，2026-11-03 定）：

- `once`：变回 `active`，`done_at` 清空。和别的 `active` 目标重名 → 报错"已有同名的目标，先改名"
- `yearly`：找自动建的下一期（`prev_goal_id` = 这一期的目标）：
  - 下一期还是 `active`、没挂交易 → 删掉下一期，这一期变回 `active`
  - 下一期挂了交易 → 报错"下一期已经挂了交易，不能撤销"
  - 下一期已经 `done` → 报错"下一期已经完成了，先撤销下一期"
  - 找不到下一期（已经被删了）→ 直接变回 `active`，同样查重名
- 优先级不变，回到原来的位置

**删除**（硬删除，没有归档）：

- 没挂交易的目标能删（`active`、`done` 都行），确认"删除目标 X？"
- 挂了交易的只能完成，删除按钮不能点，提示"挂了交易的目标不能删，可以点完成"（2026-11-03 定）
- 删了一期以后，下一期的 `prev_goal_id` 清空

**改优先级**：`/goals` 列表上每个目标有上移、下移按钮（不加拖拽库），和相邻的 `active` 目标交换优先级。第一个不能上移，最后一个不能下移。应急金不参加。

## R25.10 预算总览"还能花"

R11.1 的总览多一行（见 R11.1）：

```
为目标存 = R25.2 的每月要存合计（按今天算）
还能花   = 还剩（R11.1）− 为目标存，可以是负数
```

- 每月要存合计是 0（没有要按月存的目标）→ 不显示这一行
- 不改预算本身的上限和进度
- 首页预算那一行（R11.3）也加"还能花 $Z（已扣目标）"，合计是 0 时不加

## R25.11 `/goals` 和首页

**`/goals`**（侧边栏加"目标"；不出设计图，照 `/accounts` 和看板卡片的样子做，2026-11-03 定）：

- 不跟看板的时间段和归属人筛选
- 顶部：每月要存合计、近 3 个月实际每月存下（"基于 n 个月"）、存不过来的提示（R25.5）
- **应急金**单独一张卡片放最上面：目标金额（"月均 $X × N 个月"）、进度条（已存 / 目标）、还差、能撑几个月、挂的账户。没有应急金目标时显示"设一个应急金"按钮
- 其他 `active` 目标按优先级列，每个一行或一张卡片：
  - 名字、类型（存着的 / 要花掉的，每年重复的标"每年"）、挂的账户
  - 进度条（已存 / 目标）；没有进度时换成"没挂账户" / "账户还没有余额" / "账户已归档"
  - 还差、每月要存（或"已存够" / "没有日期" / "已过期，还差 $X，日期往后推"）
  - 预计达成（或"数据不够，估不出来" / "按现在的速度达不到"），晚了标红"比目标晚 N 个月"
  - 上移、下移按钮
  - 要花掉的：计划和实际、挂了几笔（点开看挂的交易列表，点交易进交易详情）、"买完了吗？"提示和"完成"按钮
- 下面折叠"已完成"：名字、计划、实际、差多少、完成日期（`done_at` 按 Melbourne 显示日期）、"撤销完成"、删除。按完成日期从新到旧
- 新建 / 编辑用 shadcn `Dialog` + react-hook-form + Zod。应急金的对话框只有名字、月数、账户、固定到首页
- 金额显示 `formatAud`

**首页**：

- 只显示 `active` 而且固定了的目标，每个一张小卡片：名字、进度条（没有进度时显示原因）、还差、每月要存
- 没有固定的 → 什么都不显示，不留空位
- 不跟看板筛选
- 按 `/goals` 的顺序（应急金在最前）

## R25.12 不做

- 一个目标挂几个账户
- 手动记每个目标存了多少（不做虚拟拆分）
- 自动把钱分配到目标（转账提醒、定时转账）
- 目标的历史曲线
- 按归属人分目标
- F8 按目标筛选（目标页直接列挂的交易）
