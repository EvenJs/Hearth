# R22. 月均支出和一次性开销（F11，2026-11-01 新增）

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。
> 用例见 [`fixtures/cases/12-monthly-average.md`](../../fixtures/cases/12-monthly-average.md)。

一次性只是拆分上的一个标记，**不改分类、归属人、金额**。它只影响月均（R22.5 到 R22.9）和用到月均的地方（预算默认值 R22.11，应急金 R25.6）。看板本期收入支出、汇总表、Top 商家、预算进度、税务卡片的数字都不变。

## R22.1 一次性标记

拆分上的 `is_one_off`，三种状态：

| 值 | 含义 | 统计里 |
| --- | --- | --- |
| `null` | 没看过（默认） | 不算一次性 |
| `true` | 是一次性 | 一次性 |
| `false` | 看过，确认不是 | 不算一次性 |

- 为什么要三态：房贷、房租每个月都超过阈值，只有是/否的话"大额未标"（R22.3）会永远提示。`false` 就是"看过了，别再问"
- **只有支出口径的拆分能标**（R10：kind = `expense`，加上现金支出、银行费用）。其他拆分不显示勾选框，值永远是 `null`
- 正数的支出拆分（退款）也能标。一次性买的东西退了，退款那条要**手动**标 `true`，不然退款会冲减月均。不自动配对
- 在交易详情上每个支出拆分一个勾选框（shadcn `Checkbox`）：勾上 = `true`，取消勾 = `false`。从 `false` 或 `true` 回不到 `null`
- 不做批量标一次性（批量改本来就跳过多拆分交易）
- 支出拆分挂到目标时自动设成 `true`（R25.7，M11）；取消挂不动

## R22.2 各种操作后标记怎么变

总原则：**拆分的分类改到非支出口径时，标记清成 `null`；其他情况标记不动。** 唯一例外是小票保存。

| 操作 | 标记 |
| --- | --- |
| 导入、手动录入（R17）新建主拆分 | `null` |
| 拆出一部分（R15.2） | 新拆分默认 `null`，拆分对话框里可以直接勾（只在新分类是支出口径时显示）；主拆分不变 |
| 改非主拆分金额（R15.3） | 两边都不变 |
| 删除非主拆分（R15.3） | 它的标记跟着没了；主拆分不变 |
| 改分类（R16.4）、批量改分类、规则重新应用（R7.2）、R6.4 重新识别 | 新分类还是支出口径 → 不变；改成收入、内部转账、未分类 → `null` |
| 改归属人、改备注、R17.5 改金额或日期 | 不变 |
| pending 确认（R8.3） | 保留；R8.3 例外里主拆分改成内部转账的 → `null` |
| 确认转账建议（R6.3） | 分类变内部转账 → `null` |
| 归档分类（R19.4） | 不变（归档分类的支出照算，R22.6） |
| 小票保存（R20.3） | 保存后**所有拆分都是 `null`**（包括主拆分，因为金额和分类都重排了）。保存前有任何一个拆分是 `true` 的，保存后提示一句"一次性标记已清掉，需要的话重新勾"；只有 `false` 的不提示 |
| 撤销导入（R12.1）、删除交易（R17.5） | 拆分删掉，标记跟着没了 |

写拆分的代码（`writeSplits` 的 `fields()`、导入、手动录入、pending 确认）只写列出的字段，**不要**在更新分类时顺手把 `is_one_off` 写成默认值。

拆分上挂的目标 `goal_id`（M11）照同一张表变，见 R25.8：改到非支出口径、小票保存时清成 `null`，其他不动。

## R22.3 大额未标提示

阈值 `ONE_OFF_HINT_CENTS = 50000`（$500）。prd 说"可以改"，目前就是改常量，不做设置页。

**按交易算**（同 R10.3，一笔交易算一次）：

1. 取这笔交易里支出口径的拆分
2. 有任何一个是 `true` 或 `false` → 不提示（用户看过了）
3. 这些拆分全是 `null`，且金额合计 ≤ −50000 → 提示

所以：

- 转账、收入、未分类不提示（没有支出拆分，或支出拆分合计不够）
- 拆过的交易：只加支出拆分。−700.00 拆成 −400.00 Supermarket + −300.00 未分类 → 支出合计 −400.00，不提示
- 退款（正数）不提示
- pending 照样提示
- 刚好 −500.00 提示，−499.99 不提示

**交易详情**：提示一行"这笔是一次性开销吗？"，两个按钮：

- "是"：把这笔所有 `null` 的支出拆分设成 `true`。只想标其中一部分的，直接在拆分上勾
- "不是一次性"：把这笔所有 `null` 的支出拆分设成 `false`

**F8 列表**：命中的交易行上一个小标"一次性？"；快捷筛选加"大额未标 N"，N 是本家庭所有交易里命中提示的笔数（不跟当前的其他筛选），点了只列这些交易。只提示，不自动标。

## R22.4 F8 一次性筛选

加一个筛选"一次性"：全部（默认）/ 是 / 否。

| 选项 | 条件（拆分） |
| --- | --- |
| 是 | `is_one_off = true` |
| 否 | `is_one_off` 是 `null` 或 `false`（包括收入、转账、未分类的拆分） |

和 R16.5 一样：一笔交易只要有一个拆分命中就列出；选了"是"或"否"时，合计**只加命中的拆分**。想看"没标一次性的支出"就同时选类型 = 支出。

## R22.5 月均的窗口和起点

- **完整月**：今天（`Australia/Melbourne`）所在月之前的月份。今天所在月不管过了几天都不算
- **数据起点**：本家庭最早一笔交易（任何分类、任何状态）的日期所在的月份，不管是不是 1 号。起点月算一个完整月
- 两个窗口：
  - 近 12 个月：上个月往前数 12 个月
  - 近 3 个月：上个月往前数 3 个月
- 窗口里早于起点月的月份不算。月数 n = min(12 或 3, 起点月到上个月的月数)
- n = 0（起点就在本月）→ 卡片显示"还没有完整月的数据"，不算月均，不做对比
- 卡片上写"基于 n 个月"（两个窗口各写各的）

例子：今天 2026-11-15，最早一笔 2026-06-10 → 近 12 个月是 2026-06 到 2026-10，n = 5；近 3 个月是 2026-08 到 2026-10，n = 3。

## R22.6 口径

窗口内支出合计 S 按 R10 支出口径（`bucketOf`），按交易的 `date` 归月：

- 退款冲减，pending 计入
- 转账、交税（Tax (ATO) 是收入类）不算，未分类不算
- **另外排除 `is_one_off = true` 的拆分**（`null` 和 `false` 都算）
- 归档分类的支出照算，列表里照列，名字后面标"已归档"

**月均 = S ÷ n**。某个分类有几个月是 0 也算进 n，所以各分类、各归属人的月均加起来 = 总月均。用平均数不用中位数（prd F11）。

## R22.7 取整

1. **总月均**：S ÷ n 四舍五入到分，按绝对值（同 R10.4：−500.5 → −501）
2. **各一级、各归属人**：用最大余数法，把总月均分给各行，加起来正好等于总月均
   - 每行先拿 `floor(s ÷ n)`（s 是这一行的窗口合计，负数也向下取整：−4580 ÷ 5 = −916，−1 ÷ 3 = −1）
   - 还差 k = 总月均 − Σ floor 分，按余数 `s mod n`（取 0 到 n−1 的值）从大到小，每行给 1 分，给完 k 分为止
   - 余数一样大：s 大的先拿；再一样按名字字母顺序
3. **二级**：在它的一级里再分一次，总数换成这个一级分到的月均，方法同上
4. 系统分类（现金支出、银行费用）没有二级，不展开

比较余数时用整数（`s mod n`），不要用浮点数的小数部分。

R20.3 第 3 步的整单折扣分摊是"余数全给最大的一组"，不是最大余数法，不能直接复用。M7.7-3 在 `src/lib/rules/monthly-average.ts` 里写一个 `allocateLargestRemainder`，以后要共用再提出来。

## R22.8 维度和显示

- 卡片放在看板汇总表上面，样子照现有卡片（2026-11-01 定，不出设计图）
- 两列：近 12 个月月均、近 3 个月月均；每列标"基于 n 个月"
- 维度切换：分类（一级，点开看二级）/ 归属人
- 列哪些行：两个窗口或本月（R22.9）里任一个合计 ≠ 0 的一级（或归属人）。按近 12 个月月均从大到小排，一样按名字
- 某行月均是负数照实显示
- **跟**看板的归属人筛选（R10.6）：选了某个归属人时，S 只算这个人的拆分，再按上面的规则分；按归属人看时只剩一行
- **不跟**时间段选择（同 R10.5，窗口永远按今天算）

## R22.9 本月对比

- 本月 = 本月 1 日到今天（R10.1"本月"），也**排除一次性**，和月均同口径。本月实际花了多少看 KPI 和"其中一次性"（R22.10）
- 每行显示本月金额和百分比 = (本月 − 近 12 个月月均) ÷ 近 12 个月月均。月均用卡片上显示的那个值（分配后的）
- 四舍五入按 R10.4（按绝对值，带符号，整数）；颜色同 R10.4（灰色）
- 近 12 个月月均 ≤ 0 → 显示"—"
- 卡片上标一句"本月到今天，还没过完"

例子：本月 Groceries 140.00，月均 112.60 → `+24%`。

## R22.10 本期支出"其中一次性 $X"

- 看板本期支出 KPI 下面加一行"其中一次性 $X"
- X = −Σ 本期 `is_one_off = true` 的支出口径拆分金额（退款冲减，所以可以是负数，照实显示）
- **跟**时间段和归属人筛选（R10.6）
- X = 0 不显示这行
- 本期支出本身不变，照常包括一次性

## R22.11 新建预算的默认上限

- 新建预算选了分类后，上限默认填这个分类**近 12 个月**的月均，四舍五入到**整元**（$112.60 → $113）
  - 一级：一级的月均（含它所有二级）
  - 二级：二级的月均
  - 现金支出：照样填（R11.2 允许给它设预算）
- 月均取 R22.7 分配后的值，**按全家算**，不跟看板的归属人筛选
- 月均 ≤ 0，或没有完整月（n = 0）→ 不填，留空
- 用户已经动过上限输入框，再换分类也不覆盖
- 编辑已有预算时不填
- 输入框下面一行小字："近 12 个月月均 $X（基于 n 个月）"。月均 ≤ 0 时上限留空，小字照常显示；没有完整月（n = 0）不显示。设计图里的"参考上月实际"仍然不做（design README 10）
