# R19. 分类管理（2026-10-25 新增）

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。

设置 → 分类（`/settings/categories`），新建、修改、归档一级和二级分类。表结构不变（schema `category`）。

## R19.1 列表

- 按支出、收入两组，一级按 `sort_order`，点开看二级；每个分类显示分类 tag、默认归属人、二级的"税前"标记、用了几笔（拆分数）、有几条规则指向它
- 系统分类（未分类、内部转账、现金支出、银行费用）单独列在最后，只读
- 归档的默认不显示，勾"显示已归档"才出来，灰色

## R19.2 新建

| | 一级 | 二级 |
| --- | --- | --- |
| 名字 | `name_en` 必填 | `name_en` 必填 |
| 类型 | 选支出或收入，之后不能改 | 跟一级，不能选 |
| 默认归属人 | 可选 | 可选，为空时继承一级（R5） |
| 税前 | — | 只有收入的二级能勾（`is_pre_tax_default`） |
| 自动 | 同时建一个 Other 二级（`is_other = true`） | — |

- 名字去首尾空格、多个空格合成一个，最长 50 字符，不能为空；同一个一级下（一级之间也一样）名字不区分大小写不能重复
- 和归档的分类重名也算重复，报错"已有归档的分类 X，勾'显示已归档'后取消归档就能用"，不自动取消归档（2026-10-26 补）
- 新的一级排在同组最后（`sort_order` 取最大值 + 1）；新的二级排在 Other 前面，Other 始终是最后一个（2026-10-26 补，和 seed、prod 手动加的 Bakery 一致）。不做拖动排序
- `name_zh` 不在表单里，界面照旧先显示英文（design/README 第 3 节）
- 只能建两级，二级下面不能再建
- 一级之间查重名时，系统分类和另一种类型的一级也算（它们都是一级）。例如已有支出一级 Groceries，就不能再建收入一级 groceries（2026-10-27 补）
- 归档中的一级下面可以新建二级。新二级在下拉里选不到（R16.3），一级取消归档时跟着一起恢复（2026-10-27 补）

## R19.3 修改

- 能改：名字、默认归属人、税前（收入的二级）
- 不能改：类型、所属一级（不能把二级挪到别的一级下）
- Other：不能改名，能改默认归属人、税前
- 系统分类：都不能改
- 改名也按 R19.2 查重名（同一个一级下、一级之间，含归档的），自己不算；Other 原样传回 `Other` 不算改名。类型、所属一级传回原值也不算改（2026-10-27 补）
- 改名字：交易、规则、拆分都按 id 关联，跟着变，不用迁移
- 改默认归属人、税前：**只影响以后**（新导入、新录入、以后 R5.1 重算的）。已有交易不批量重算，要改就去 F8 批量修改
- seed 的一级颜色是按名字固定的（`category-color.ts`），改了名字就按 id 挑色，颜色可能会变。可以接受

## R19.4 归档

不能删除，只能归档（tech-stack：业务数据软删除）。

- 系统分类、Other 不能单独归档；Other 跟着一级一起归档
- 归档一级 = 一级和它下面所有二级一起归档
- **有规则指向它（归档一级时包括它的二级）就不能归档**，提示"有 N 条规则指向这个分类，先去规则页改掉或删掉"，链接带上分类筛选。不然导入时规则会把交易分到归档的分类里
- 归档以后：
  - 改分类、拆分、快速录入、规则的分类下拉里都不能选（R16.3）
  - 已有交易不动，统计照常算（R10），看板和汇总表里照常出现
  - F8 的分类**筛选**里还能选，放在最后、灰色，方便查历史
- 取消归档：二级的一级还在归档中时不能单独取消，先取消一级（一级取消归档时二级跟着恢复）
- 一级取消归档时，下面所有二级都恢复，包括一级归档前就单独归档过的：表里不记归档顺序，不为这个改表（2026-10-26 补）

## R19.5 和 seed 的关系

同 R18.5：seed **只在本家庭还没有分类时**插分类和规则（第一次 seed）。之后再跑 seed 只补 member、household_user，不碰 `category`、`category_rule`。以后 `seed-categories.md` 新加的分类和规则，已有家庭在管理页手动建。
