# R26. 邀请码注册（F15，2026-11-08 新增，M12）

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。
> 用例见 [`fixtures/cases/17-invite.md`](../../fixtures/cases/17-invite.md)。方案见 `docs/proposals/2026-11-04-signup-invite.md`，边界情况的结论见 `docs/tasks/m12.md`（M12-0，2026-11-08 定）。

注册一直开着，但必须有有效邀请码。`join` 码进发码人的家庭，`new_household` 码注册后建一个新家庭。要验证邮箱，没验证不能登录；有忘记密码、改密码、改名字。小票 LLM 识别每个家庭每月有限额。

- 码的生成、格式、状态、谁能发、注册校验顺序、新家庭的归属人映射、限额的判断都是**纯函数**（`src/lib/rules/invite.ts`、`src/lib/rules/llm-quota.ts`），"现在"当参数传进来，不自己取
- 注册接 Better Auth 用**方案 a**：保留 `disableSignUp: true`，注册走自己的 Server Action，照 `scripts/create-user.ts` 用 `$context` 建用户和密码，和邀请码在同一个事务里（R26.5）。`$context` 是半内部 API，升级 better-auth 要重测注册和 `user:create`
- 邀请码、密码、重置链接、验证链接**不打日志**，错误信息里也不带
- 时间：码的过期看 `expires_at`（timestamptz），和"现在"直接比，不换时区；限额按 Melbourne 自然月（R26.9）；界面上显示的时间按 Melbourne
- 错误提示中文。除了"这个邮箱已经注册了"，不暴露内部原因（数据库错误、哪一步失败）
- `pnpm user:create` 留着当后门（邮件发不出去、要手动补账号时用）
- 不做：退出家庭、删账号、改邮箱、第三方登录

## R26.1 码的格式和生成

- **字符集**：大写字母和数字，去掉容易混的 `0`、`O`、`1`、`I`、`L`，共 31 个，顺序固定为 `ABCDEFGHJKMNPQRSTUVWXYZ23456789`
- **长度**：8 位
- **存**：8 位大写，不带横杠（`HX7K29QD`），`invite.code` 唯一
- **显示**：`XXXX-XXXX`（`HX7K-29QD`），复制出来也是带横杠的
- **生成**：每一位用 `crypto.randomInt(31)` 取字符集里的一个（不用 `Math.random`，不用取模）。纯函数把随机数来源当参数传进来，测试里固定。插入撞了唯一约束就重新生成，最多 5 次，还撞就报错"生成邀请码失败，再试一次"
- **输入整理**（注册时）：去掉所有空白（空格、Tab、换行）和横杠 `-`，转大写。整理完不是 8 位、或者有字符集以外的字符，当"不存在"（R26.4 第 2 条）。不做 `0 → O`、`1 → I` 这类自动纠正（字符集里本来就没有这些）
- 有效期：**3 天**，`expires_at = created_at + 72 小时`（按绝对时间算，夏令时切换那天也是 72 小时）。只能用一次

## R26.2 用途和谁能发

| 用途 | 谁能发 | 发码时要填 | 码上存 |
| --- | --- | --- | --- |
| `join` 加入我们家 | 任何登录用户（站长也一样） | 归属人：本家庭、**没归档**的 member，kind 不限（Home 也行） | `household_id` = 发码人的家庭，`member_id` = 选的归属人 |
| `new_household` 新建家庭 | 只有站长 | 不用填 | `household_id`、`member_id` 都是 `null` |

**站长**：`ADMIN_EMAILS` 按逗号分开，每一项去首尾空格、转小写，空的项丢掉；登录用户的邮箱转小写以后**完全相等**才算（不是包含，`admin@example.com.au` 不等于 `admin@example.com`）。

- `ADMIN_EMAILS` 没配、是空字符串、或者只有逗号和空格：没人是站长。设置 → 邀请**不显示**"新建家庭"选项
- 站长判断只在**发码时**做。码发出去以后把这个人从 `ADMIN_EMAILS` 拿掉，已经发的码照样能用
- 一个归属人可以对应多个登录用户，发 `join` 码时不管这个归属人是不是已经关联了别的用户
- 发码数量不限

**发码时的校验**，按顺序：

| # | 情况 | 错误 |
| --- | --- | --- |
| 1 | `new_household`，不是站长 | 只有站长能发新建家庭的邀请码 |
| 2 | `join`，没选归属人 | 请选归属人 |
| 3 | `join`，归属人不是本家庭的，或者已经归档了 | 归属人不对，刷新页面再试 |

## R26.3 码的状态、撤销、列表

**状态**（实时算，不存），按顺序第一条命中的就是：

| # | 条件 | 状态 |
| --- | --- | --- |
| 1 | `revoked_at` 不为空 | 撤销 |
| 2 | `used_at` 不为空 | 已用 |
| 3 | 现在 ≥ `expires_at` | 过期 |
| 4 | 其他 | 没用 |

- **刚好到 `expires_at` 那一刻就算过期**（差 1 秒还能用）
- 已用的码过了 `expires_at` 还是显示"已用"

**撤销**：只能撤销**自己发的**、状态是**没用**的码。记 `revoked_at = 现在`。

| # | 情况 | 错误 |
| --- | --- | --- |
| 1 | 码不存在，或者不是自己发的 | 只能撤销自己发的码 |
| 2 | 状态不是"没用" | 只有没用的码能撤销 |

撤销不影响已经注册的人。撤销了不能恢复，要用就再发一个。

**列表**（设置 → 邀请）：只列**自己发的**码，按 `created_at` 新的在前。每行：码（`XXXX-XXXX`）、用途、归属人（`join`）、状态、过期时间、谁用了（用户名字）、什么时候用的。"没用"的有"复制"和"撤销"按钮。

## R26.4 注册：校验顺序和提示

注册表单：邮箱、名字、密码、邀请码。

**字段整理**：

- 邮箱：去首尾空格、转小写，Zod `email()` 校验
- 名字：去首尾空格、多个空格合成一个，1 到 30 个字符
- 密码：8 到 128 个字符（Better Auth 默认），不去空格
- 邀请码：按 R26.1 整理

**校验顺序**，第一条不过就报错、不建账号、不动码：

| # | 情况 | 提示 |
| --- | --- | --- |
| 1 | 字段不合格（邮箱格式、名字空或超过 30、密码不到 8 或超过 128） | 字段下面分别提示：邮箱格式不对 / 请填名字 / 名字最多 30 个字 / 密码至少 8 位 / 密码最多 128 位 |
| 2 | 码整理后格式不对，或者找不到 | 邀请码不对，检查一下有没有输错 |
| 3 | 码已撤销 | 这个邀请码已经撤销了，找发码的人要个新的 |
| 4 | 码已用 | 这个邀请码已经用过了 |
| 5 | 码过期 | 这个邀请码过期了，找发码的人要个新的 |
| 6 | `new_household`，名字是"共同" | 名字不能叫"共同" |
| 7 | 邮箱已经注册（不区分大小写） | 这个邮箱已经注册了，去登录（带登录页链接） |

- 3、4、5 的顺序和 R26.3 的状态顺序一样（又撤销又过期的提示撤销）
- **码先校验、邮箱后校验**：没有有效码的人不能拿注册页试出哪些邮箱注册过
- 第 7 条**码不作废**，还能拿去注册别的邮箱
- 第 6 条：新家庭的"共同"归属人已经叫这个名字，`member` 有 `(household_id, name)` 唯一。`join` 不建归属人，名字叫"共同"没关系

## R26.5 注册事务

R26.4 都过了以后，**一个事务**里按顺序做，任何一步失败全部回滚（没有用户、没有家庭、码还是没用）：

1. 建用户（`email_verified = false`）和密码（Better Auth 的 `account` 表，`provider_id = credential`）。邮箱撞了唯一约束（两个人同时用同一个邮箱）→ 回滚，提示 R26.4 第 7 条
2. **把码标成已用**：条件 UPDATE

   ```sql
   update invite set used_at = 现在, used_by = 新用户 id
   where id = 码 id and used_at is null and revoked_at is null and expires_at > 现在
   ```

   改到 0 行（刚被别人用了、刚被撤销、刚过期）→ 回滚。重新读这个码，按 R26.4 第 3 到 5 条给提示；都不是的话提示"注册没成功，再试一次"
3. 按用途：
   - `join`：建 `household_user`（`household_id` = 码上的家庭，`member_id` = 码上的归属人，**归属人归档了照样用**，进来以后自己改）
   - `new_household`：建家庭和 seed（R26.6），建 `household_user`（`member_id` = 新建的那个 person 归属人）
4. 提交

**两个人同时用一个码**：靠第 2 步的条件 UPDATE，只有一个能改到 1 行，另一个回滚，提示"这个邀请码已经用过了"。不用 `SELECT ... FOR UPDATE`。

**提交以后**（不在事务里）：发验证邮件（R26.7）。

- 发出去了：注册页显示"验证邮件已经发到 xxx，点邮件里的链接再登录"
- 没发出去（SMTP 密码错、超额、超时）：**账号已经建好**，不回滚。注册页显示"注册成功了，但验证邮件没发出去，请联系站长"。站长可以用 SQL 把 `email_verified` 设成 `true`，或者让他去登录页"重发验证邮件"
- 注册完**不自动登录**

## R26.6 新家庭 seed 什么

复用 `seedHousehold`（`src/server/seed.ts`）的分类和规则部分，在 R26.5 的事务里跑（M12-3 改成能接外面传进来的事务）。

| 建什么 | 内容 |
| --- | --- |
| household | 名字 `<名字>的家`（如 `Alex的家`，名字和"的家"中间不加空格）。以后在设置页改 |
| member | 两个：注册的人（名字 = 注册时填的名字，`person`，`sort_order` 0）、`共同`（`shared`，`sort_order` 1）。**不建** `Male`、`Female`、`Home` |
| category | `seed-categories.md` 第 2 到 4 节全部（支出、收入、系统分类），和我们家第一次 seed 一样 |
| category_rule | `seed-categories.md` 第 5 节全部 |
| household_user | 新用户 → 新家庭，`member_id` = 注册的人 |

**分类默认归属人的映射**（`seed-categories.md` 里写的是我们家的名字）：

| seed 里写的 | 新家庭用 |
| --- | --- |
| `Male` | 注册的人 |
| `Female` | 注册的人 |
| `Home` | 共同 |
| 空 | 空 |

现在 seed 里只有 Home & utilities、Insurance & financial、Groceries 设了 `Home`，所以新家庭这三个是"共同"，其他是空。`Male`、`Female` 的映射是给以后加的条目留的。

**不建**：账户、卡、预算、目标、税务资料、每月条件。让他自己建。

## R26.7 邮箱验证和登录

- **没验证不能登录**（Better Auth `requireEmailVerification: true`）。登录时邮箱密码对、但没验证：提示"邮箱还没验证，去邮箱点验证链接"，下面一个"重发验证邮件"按钮
- 邮箱或密码不对：照旧提示"邮箱或密码不对"，不区分是哪个
- **验证链接 24 小时过期**。过期了点进去：提示"链接过期了，回登录页重发验证邮件"
- 点验证链接成功：`email_verified = true`，自动登录，进看板
- **重发验证邮件**：登录页能点。**同一个邮箱 60 秒一次**，60 秒内再点提示"刚发过，X 秒后再试"（X 向上取整）。上一封的发送时间记在 Better Auth 的 `verification` 表（M12-4 定，不改表）：`identifier = throttle:<verify-email|reset-password>:<邮箱>`，`expires_at` = 发送时间 + 60 秒。按输入的邮箱记，邮箱不存在也记。注册后发的那封也记
  - 不管邮箱存不存在、是不是已经验证，都提示同一句"如果这个邮箱注册了还没验证，验证邮件已经发出去了"。邮箱不存在或已验证就不发
- **现有用户**（`user:create` 建的）：M12-3 的迁移里把现有用户的 `email_verified` 都设成 `true`，上线后照常登录
- `user:create` 以后建的用户也直接设 `email_verified = true`（站长手动建的不用验证）

## R26.8 忘记密码、改密码、改名字

**忘记密码**（登录页"忘记密码"）：

- 填邮箱，发重置链接。不管邮箱存不存在，都提示"如果这个邮箱注册过，重置链接已经发出去了"。同一个邮箱 60 秒一次，和 R26.7 重发一样
- **重置链接 1 小时过期，只能用一次**（Better Auth 默认，存 `verification` 表）。过期或用过：提示"链接过期了，重新申请"
- 新密码 8 到 128 位，填两遍要一样
- 重置成功：**这个用户所有 session 全部退出**（Better Auth `revokeSessionsOnPasswordReset: true`），跳登录页提示"密码改好了，请登录"
- 没验证邮箱的人也能重置密码，但重置完还是要先验证才能登录

**改密码**（设置 → 账号）：填当前密码、新密码两遍。当前密码不对提示"当前密码不对"。改好以后**其他设备的 session 退出**，当前这个保留。

**改名字**（设置 → 账号）：校验和注册一样（R26.4）。只改 `user.name`，**不改归属人的名字**（归属人在设置里另外管）。

**邮箱**：设置 → 账号只显示，不能改。

## R26.9 小票识别限额

**限额**：每个**家庭**每月 `RECEIPT_LLM_MONTHLY_LIMIT` 次，家里所有人一起算。环境变量没填、不是正整数（`abc`、`0`、`-5`、`12.5`）都当 50。

**算一次**：真的向 LLM 发了请求就算一次，**不管成功失败、存没存小票**。发请求**之前**先写一条 `llm_usage`（`purpose = receipt`），再调用。

**不算**：

- `RECEIPT_READER=none`
- `RECEIPT_READER=llm` 但没配 `LLM_*`（没发请求，R20 的"暂时识别不了"）
- 到了限额被挡下来的
- 粘贴文字、手动填商品

**本月用了几次**：本家庭 `purpose = receipt`、`created_at` 换成 Melbourne 时间以后在本月（Melbourne 自然月）的 `llm_usage` 条数。

- 11 月 30 日 23:59（Melbourne）算 11 月，12 月 1 日 00:00 算 12 月。注意两个都是 UTC 的 11 月 30 日
- 每个月 1 日 00:00（Melbourne）重置，不用跑任务，按月数就行

**判断**（调用前）：

| 情况 | 结果 |
| --- | --- |
| 本月用了 < 限额 | 能识别。小票页显示"本月还能识别 X 次"，X = 限额 − 用了 |
| 本月用了 ≥ 限额 | 识别按钮变灰，写"本月识别次数用完了，M 月 1 日恢复"（M 是下个月，12 月的时候是"1 月 1 日"）。粘贴文字和手动填照常 |

- `RECEIPT_READER` 不是 `llm` 时不显示次数
- 两个人同时点、刚好卡在最后一次：都可能通过，本月最多多出几次。不加锁（一个家庭两三个人，不值得）
- 服务端调用前再判断一次，不只看按钮（按钮是页面打开时的状态）

## R26.10 和其他规则的关系

- **R20.1**：reader 怎么选不变。`llm` reader 调用前先过 R26.9 的限额
- **R16.3 / 数据隔离**：新家庭的数据靠 `household_id` 隔开，和我们家完全分开。注册页、忘记密码页、重置密码页、验证链接是登录前的页面，不走 `getHouseholdContext`
- **R5 归属人**：`join` 进来的人关联的归属人只决定"这个登录用户是谁"（`household_user.member_id`），不改任何交易的归属人
- **R18.5、R19.5**：新家庭第一次 seed 插分类和规则，之后和我们家一样在设置页管
- 税务、ANZ / CBA 账户配置、每月条件是按我们家写的，别的家庭用起来可能不合适，这次不管
