# R23. 账户余额和用途（F12，2026-11-03 新增，M9）

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。
> 用例见 [`fixtures/cases/14-balance.md`](../../fixtures/cases/14-balance.md)。

余额只按 `transaction.amount_cents` 算，**不看拆分、分类、转账状态**：内部转账也是钱进出，照样算。M9 不改任何统计口径，看板、F8、预算、税务、月均的数字都不变。

## R23.1 锚点

锚点 = 某个账户"**某一天结束时**的余额"。两种来源（2026-11-02 定：以后都优先用 PDF，CSV 的余额不用）：

| 来源 | 金额 | 日期 | 从哪来 |
| --- | --- | --- | --- |
| PDF 批次 | `import_batch.closing_balance_cents` | `import_batch.date_to`（账期结束日） | `source = pdf` 的批次：ANZ（R1C）、ANZ Plus（R1D）、CBA（R1E） |
| 手动 | 填的金额 | 填的日期 | `account_balance` 表（M9-3 建） |

- 为什么 `date_to` 当天的交易已经在余额里：R1C 是 `(periodFrom, periodTo]`，R1D、R1E 是 `[periodFrom, periodTo]`，结束日都包含在内
- 按来源写，不写死银行：以后别的银行有了 PDF 解析器，`source = pdf` 就自动当锚点
- PDF 的余额**不另存**。撤销导入（R12.1）删了批次，这个锚点就跟着没了，自动退回上一个锚点
- **CSV 批次不当锚点**：CBA CSV 自动算出的期末（R1B.2）、ANZ CSV 手动填的期末（R9）都不用，哪怕它的 `date_to` 比 PDF 晚。CSV 导进来的交易照样算进"锚点之后的交易"
- 以对账单为主：PDF 期末是银行给的正本。手动只是兜底，给没有对账单的账户（现金、中转）或两份对账单之间想核对时用

**选哪个锚点**（每个账户只用一个）：

1. 日期最晚的
2. 同一天有几个 → PDF 优先于手动
3. 同一种来源 → `created_at` 最晚的

**新建账户的开户余额**（2026-11-02 定）：

- 新建表单有"开户余额"，默认 $0（现金账户填钱包里现在有多少，信用卡填负数）
- 保存时在同一个事务里写一条手动锚点：金额 = 开户余额，日期 = 建账户那天（Melbourne）的**前一天**。这样建账户当天的交易也算进去
- 写进去以后和别的手动锚点一样：可以删（R23.3），删了这个账户就没有余额了

**没有锚点的账户**：

- 已有的账户（现金、CBA 对账单导入以前的 CBA、已经建好的中转账户）、删掉了所有锚点的账户：**不显示余额**，显示"还没有余额，填一次"，不算进合计
- 不从 $0 开始累加：建账户以前的钱 app 不知道
- 迁移**不**给已有账户补 $0 锚点，只有新建时自动写

## R23.2 入账余额和可用余额

设选出的锚点是 `(A, D)`（金额 A，日期 D），只看这个账户的交易：

```
入账余额 = A + Σ amount_cents（status = confirmed，date > D）
可用余额 = 入账余额 + Σ amount_cents（status = pending，date > D）
截至     = max(D, date > D 的交易里最晚的日期)，pending 也算
```

- 像银行的"余额 / 可用余额"（2026-11-02 定）。入账余额对应网银的余额；可用余额把月中录的 pending（小票 R20.5、手动录入 R17）马上减掉，不用等导入
- **`date = D` 的交易不算**，不管它什么时候导进来：按定义已经在锚点里了。所以手动校准要填"某天结束时"的数
- **日期不晚于 D 的 pending 也不算**（2026-11-03 定）。银行那笔导进来时 R8.2 会配上它，日期改成银行日期（R8.3），又会算进入账余额，只差几天。PDF 锚点前面没配上的旧 pending 也不会一直挂在余额里
- 不会重复算：导入时 R8.2 把 pending 配上银行那笔，变成同一笔 confirmed，可用余额不变、入账余额跟上。没配上的 pending 会和银行那笔重复，F8 已经提示"可能重复"（R17.6），删掉多的就对了
- 现金、其他银行的手动录入直接是 confirmed（R8.1），两个数一样
- 信用卡：余额是负数，照样算
- 归档的账户：不算，不显示

**显示**：

- 没有 pending（`date > D` 的 pending 0 笔）：只显示一个数
- 有 pending：大字是可用余额，下面小字"入账 $X，含 N 笔待确认 $Y"（Y 是 pending 合计，带符号）
- 旁边显示"截至 YYYY-MM-DD"、锚点来源："对账单期末"（PDF）或"手动填的"（手动）

## R23.3 手动校准和差额

**填一个手动余额**：

- 输入：账户、日期、金额（分，可以是 0 或负数）
- 日期默认**昨天**（Melbourne），可以改，不能晚于今天。旁边一行小字"填这一天结束时网银显示的余额；今天的交易可能还没全部入账，所以默认昨天"
- 日期可以早于最近的 PDF 锚点（比如补填半年前的数）：它只是一个更早的锚点，不影响当前余额，只参与对比
- 归档的账户不能填；账户要属于本家庭
- 只能删，不能改（填错了就删了重填）。删的时候校验属于本家庭

**差额**（手动锚点 M，日期 D，金额 X）：

1. 前一个锚点 P = **除 M 以外**、日期 ≤ D 的所有锚点（PDF + 手动）里，按 R23.1 的顺序选出的那个。同一天的 PDF 也算，所以和对账单同一天填的数会直接和对账单期末比
2. 没有 P（这个账户第一次填，或者填的日期比所有锚点都早）→ 不比较，不提示，差额是 `null`
3. 预期 = P 的金额 + Σ amount_cents（status = confirmed，P 的日期 < date ≤ D）。**只和入账余额比，不算 pending**：网银的余额不含 app 里还没入账的那些
4. 差额 = X − 预期。和 R9 一样：负数说明网银比 app 少，app 里可能漏了支出或多了收入；正数相反

- 差额 ≠ 0 → 保存后提示"和算出来的差 $X，可能漏导了交易"（$X 用 `formatAud`，带符号）。**照样保存**，填的数成为锚点
- 差额**每次实时算，不存**：后来补导了漏的交易、或者在 P 前后导了新的对账单，预期变了，提示跟着变或消失
- 开户余额那条锚点（R23.1）一般没有 P，所以不比较

**账户卡片上**：只看最近一次手动校准（手动锚点里日期最晚的，同一天看 `created_at` 最晚的），差额不是 `null` 也不是 0 → 显示"上次校准差 $X"。不管它是不是当前用的那个锚点

## R23.4 用途和关联账户

**用途**：`financial_account.purpose`，和 `type` 分开（`type` 是银行账户类型，用途是这笔钱拿来干嘛，prd F12）

| 值 | 显示 |
| --- | --- |
| `everyday` | 日常 |
| `bills` | 账单 |
| `emergency` | 应急金 |
| `savings` | 储蓄 / 高息 |
| `goal` | 目标 |

- 已有账户迁移后都是 `everyday`，自己在设置页改
- 现金账户也有用途，不特殊处理
- 用途、类型、银行不做组合限制（比如信用卡也能选"储蓄"），M10 用到再说

**关联账户**：`financial_account.linked_account_id`，一个账户最多关联一个，可以不关联

保存时**只在关联账户改变时**校验（没改的不重新校验，所以已经关联、后来归档了的账户不会让保存失败）。按顺序，第一条不过就报错、不保存：

| # | 情况 | 错误 |
| --- | --- | --- |
| 1 | 关联到自己 | 不能关联自己 |
| 2 | 目标不存在或不是本家庭的 | 找不到这个账户（不说是别的家庭的） |
| 3 | 目标已归档 | 不能关联已归档的账户 |
| 4 | 自己是现金账户（`bank = cash`） | 现金账户不能关联别的账户 |
| 5 | 目标是现金账户（`bank = cash`） | 不能关联现金账户 |

- 设成"不关联"（`null`）不校验
- **允许互相关联**（A → B 同时 B → A，2026-11-03 定）。M9 只存、只显示，不用这个关系算东西
- 不限定"saver 才能关联 everyday"
- 被关联的账户后来归档了：关联不动，显示"B（已归档）"
- 表单的下拉列表里去掉自己、已归档的、现金账户；现金账户的表单不显示这一项

## R23.5 账户总览 `/accounts`

- 只看没归档的账户。**不跟**看板的时间段和归属人筛选
- 按用途分组，顺序：日常、账单、应急金、储蓄 / 高息、目标。组里没有账户的不显示（只有没余额的账户也显示这个组）
- 组里账户按名字排
- 每组显示组合计 = 组里有锚点的账户的**可用余额**合计
- 页面顶部：所有有锚点的账户的可用余额合计
  - 下面小字"入账合计 $X"：只在有 pending 时显示（任何一个账户有 `date > D` 的 pending）
  - "不含 N 个还没有余额的账户"：N 是 0 就不显示
- 每个账户：名字、银行、尾号、余额（R23.2 的显示）、截至哪天、锚点来源、关联账户（R23.4）、本财年利息（R23.6）、上次校准差（R23.3）；没锚点的显示"还没有余额，填一次"
- 信用卡的负余额照样加进组合计和总合计
- 不含 super、投资、净资产

## R23.6 利息

- 每个账户：**本财年**（7 月 1 日到今天，Melbourne）这个账户的交易上、分类是 `Income / Interest` 的拆分金额合计
- 为什么本财年：利息要报税（seed-categories 里 Interest 计入应税收入）
- 和 R10 一样：负数的拆分（利息冲正）直接冲减；pending 也算
- 只看拆分的分类，一笔交易拆了一部分到 Interest，只算那一部分
- 没有利息显示 $0.00

## R23.7 不做

- 余额历史曲线
- 从余额差反推漏导了哪几笔
- 一个账户里的虚拟拆分（N2.3）

每月末余额（`balanceAt`）和关联账户的每月条件见 R24（R24.4、R24.1）。
- super、投资、净资产
