# R14. 税后估算

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。

**只是估算，不是税务建议。** 没有算业务开支抵扣、各种 offset、Medicare levy 低收入减免，所以结果偏保守（偏高）。实际以 ATO 和会计为准。

B2B 收入不含 GST（没有注册），到账金额全额算税前收入。

代码放 `src/lib/tax/`，纯函数。

## R14.1 财年

- 7 月 1 日到次年 6 月 30 日，用开始年份表示：`2026` = 2026-27
- 交易按 `date` 归入财年

## R14.2 每人的税前收入

对每个 kind = person 的归属人，在一个财年内：

```
preTaxIncome = Σ 拆分金额（is_pre_tax = true，member = 这个人）
             + Σ 拆分金额（is_pre_tax = true，member kind = shared）÷ person 人数
```

- Home 名下的税前收入（如 joint account 的利息）在所有 person 之间平分，报税时一般就是这样分
- 平分除不尽的分，余数给排序靠前的人

## R14.3 计算

```
payg_gross    = tax_profile.payg_gross_cents     不为空就用（实际数），否则用 R14.9 折算工资
payg_withheld = tax_profile.payg_withheld_cents  不为空就用（实际数），否则用 R14.9 折算已代扣
preTaxIncome  = R14.2 的税前收入，利息部分换成 R14.10 的
taxable   = payg_gross + preTaxIncome          （没有 tax_profile 也没有在职段时 payg 为 0）
incomeTax = 按当年税率表分档计算(taxable)
medicare  = taxable × 2%
total     = incomeTax + medicare
prepaid   = −Σ Tax (ATO) 分类里该人的负数拆分（只算负数，退税不算）
owing     = total − payg_withheld − prepaid    （负数表示预计退税）
```

- `taxable` 先向下取整到整元，再按分档算
- 结果四舍五入到分

## R14.4 税率表（resident，不含 Medicare levy）

写在 `src/lib/tax/rates.ts`，按财年存。新财年的税率要手动加，没有该财年的表时报错，不要沿用旧表。

| 应纳税收入          | 2025-26 | 2026-27 |
| ------------------- | ------- | ------- |
| $0 – $18,200        | 0%      | 0%      |
| $18,201 – $45,000   | 16%     | 15%     |
| $45,001 – $135,000  | 30%     | 30%     |
| $135,001 – $190,000 | 37%     | 37%     |
| $190,001 以上       | 45%     | 45%     |

2027-28 起第二档降到 14%，其他档开工时再确认后加入。

## R14.5 例子（2026-27）

| 场景          | payg_gross | 税前收入 | taxable | incomeTax | medicare | total  |
| ------------- | ---------- | -------- | ------- | --------- | -------- | ------ |
| A：工资 + B2B | 60,000     | 30,000   | 90,000  | 17,520    | 1,800    | 19,320 |
| B：B2B 跨档   | 40,000     | 10,000   | 50,000  | 5,520     | 1,000    | 6,520  |
| C：只有 B2B   | 0          | 30,000   | 30,000  | 1,770     | 600      | 2,370  |

场景 A 算 owing：假设 payg_withheld = 9,720（正好是 60,000 工资单独的税），已预缴 900 → owing = 19,320 − 9,720 − 900 = **8,700**。

场景 B 说明为什么不能用"税前收入 × 边际税率"：10,000 的 B2B 实际多出 2,450 的税（一半在 15% 档、一半在 30% 档，加 2% Medicare），用 32% 直接乘会得到 3,200。

场景 D：Home 名下有 100.00 利息，Male 和 Female 各算 50.00。

## R14.6 显示

- 看板上每个 person 一张卡片：本财年应纳税收入、预计总税额、已缴、**预计年底补税**
- 卡片上的收入用 `taxable`（工资 + R14.2 的税前收入），不用 R14.2 的税前收入，否则没算工资，看起来税比收入还多（2026-10-30）
- **没有任何工资信息**（这个财年没有在职段落进来，R14.9 天数都是 0；`payg_gross` 也没填，没有行或这一格为空）：大字"还没填工资"，代替补税金额；小字"按工资 0 算，预计补税 $X"（X = 按 payg_gross 为 0 算出的 owing），带链接去设置页（2026-11-14 改）
  - 只填了实际已代扣、没有在职段也没填工资总额，照样算"没有任何工资信息"
  - `payg_gross` 填了 0 是"填过了，没有工资"，正常显示补税金额，不算没有工资信息（R14.8）
- 没填预计全年利息（R14.10）、已到账利息 > 0：卡片底部小字"利息只算到 MM-DD，全年会更多"（2026-11-14 加）
  - 日期 = 这个人"有利息的账户"里最早的"数据截至"（R24.6）。有利息的账户 = 这个财年里有 Income / Interest 拆分、归属人是这个人或 shared 的交易所在账户
  - 这些账户都没有截至日期时不写日期，小字改成"利息只算到账的部分，全年会更多"
  - 填了预计全年利息，或已到账利息是 0，不显示
- 卡片的"已缴" = `payg_withheld + prepaid`，合成一个数；设置页的估算表里分开列"已代扣"和"已预缴 (ATO)"（2026-10-30）
- 已预缴只从 Tax (ATO) 拆分算（R14.3），设置页只读显示，不能手填（2026-10-30）
- 卡片固定用**今天所在的财年**，不跟看板的时间段走（2026-10-30）
- 归属人筛选：选某个 person 只显示他的卡片；选"全部"或 Home 时所有 person 的卡片都显示（2026-10-30）
- 卡片上写明"估算，以 ATO 为准"
- 设置页（2026-11-14 加）：每个 person 一块，上面是在职段列表（新增、编辑、删除，R14.9），下面是"实际数（可选）"：工资总额、已代扣、预计全年利息，三格都可以空。估算表里工资、已代扣、利息每个数后面标"折算"或"实际"（利息标"预计"或"已到账"）

## R14.7 没有税率表的财年（2026-10-30 加）

- 看板：当前财年没有税率表时，税务卡片位置显示"缺 2027-28 税率表，去 `src/lib/tax/rates.ts` 加上"，看板其他区块照常显示，不能整页报错
- 设置页的财年下拉只列有税率表的财年，默认选今天所在的财年；今天所在的财年没有税率表时，默认选有表的最近一个，并显示同样的提示
- `tax_profile` 只能保存有税率表的财年
- 在职段（R14.9）不按财年存，保存时不检查税率表。折算已代扣要用税率表，财年没有表时照上面报错（2026-11-14 加）

## R14.8 清除工资信息（2026-11-04 加）

- 清除 = 删掉这一行 `tax_profile`（这个人、这个财年），工资总额、已代扣、预计全年利息一起清，不是把金额改成 0。改成 0 是"填过了，没有工资"，和"还没填"不一样（R14.6）
- 清除后实际数都回到"空"：工资、已代扣用 R14.9 折算，利息只算已到账（R14.10）。这个财年也没有在职段时，设置页显示"还没填，估算按工资 0 算"，看板卡片显示"还没填工资"（R14.6）（2026-11-14 改）
- 在职段（R14.9）不受清除影响，要删在职段在列表里单独删（2026-11-14 加）
- 只清这一个人、这一个财年，别的财年、另一个人的记录不动
- 只删本家庭的：`household_id` + `member_id` + `financial_year` 三个条件一起
- 只在填过的卡片上显示"清除"按钮，没填的不显示
- 清除前要确认："清除 {名字} {财年} 财年的工资信息？清除后估算按工资 0 算。"
- 记录已经不在（比如另一个人刚清了）→ 照样算成功，刷新页面
- 不检查税率表（和 R14.7 的保存不同）：页面上只能选到有表的财年，删除本身没有风险
- 已预缴 (ATO) 来自交易拆分（R14.3），不受清除影响

## R14.9 工资：在职段折算（2026-11-14 加）

每份工作存一行在职段（`tax_job`）：归属人（只能是 kind = person）、雇主（可空，只用来显示）、年薪（税前，**不含 super**）、开始日期、结束日期（可空 = 还在职）。一份工作跨财年也只存一行，每个财年各自折算。

某人某财年 F（R14.1，7 月 1 日到次年 6 月 30 日）：

```
天数(job)   = [开始, 结束] ∩ [F 开始, F 结束] 的天数，两头都算；结束为空 = F 结束；不相交 = 0
财年天数    = F 的天数：365，包含 2 月 29 日的是 366（2027-28 = 366）
折算工资    = Σ 年薪 × 天数(job) ÷ 财年天数
折算已代扣  = Σ total(年薪) × 天数(job) ÷ 财年天数
```

- `total(年薪)` = 把年薪当 `taxable` 照 R14.3 算的 incomeTax + medicare（先取整元，用 F 的税率表）。这就是"全年都拿这个年薪"的 PAYG 扣法
- 每份工作分别四舍五入到分，再加起来。设置页列表里每份工作显示的折算数加起来等于合计
- 结果进 R14.3：`tax_profile` 的工资总额、已代扣**各自**不为空就用实际数，为空才用折算。可以只填实际已代扣、工资还用折算
- 已有的 `tax_profile` 行原样保留，金额照旧当实际数生效。想改用折算，把那一格清空再保存
- 天数用 `periods.ts` 的日期工具算，日期是 `YYYY-MM-DD` 字符串，不转 `Date`
- 同一时间两份工作照样都算，不报错
- 只是近似：没算第二份工作不享受免税额度（第二份实际扣得更多）、奖金、无薪假。中途入职的人按全年年薪扣，折算已代扣会比折算工资的实际税多，看板显示预计退税是对的
- 保存时检查：开始日期晚于结束日期 → 报错"结束日期不能早于开始日期"；开始等于结束 = 1 天，可以保存；年薪必须 > 0
- 删除在职段要确认："删除 {名字} 的在职段 {雇主或'这份工作'}（{开始} 到 {结束或'现在'}）？所有财年的折算都会变。"
- 只删、只改本家庭的：带 `household_id`

**例子**（2026-27，365 天）：年薪 120,000，2027-01-01 入职，还在职 → 天数 181 → 折算工资 59,506.85，折算已代扣 28,920 × 181 ÷ 365 = 14,341.15

## R14.10 利息：预计全年（2026-11-14 加）

`tax_profile` 上有一格可以为空的"预计全年利息"（`expected_interest_cents`），按人填。Home 名下的利息自己算好各人那一半填进去。

```
已到账利息 = R14.2 里分类是 Income / Interest 的部分（Home 的照样按 R14.2 平分）
利息部分   = 预计全年利息为空 → 已到账利息
            否则 → max(预计全年利息, 已到账利息)
preTaxIncome = (R14.2 的税前收入 − 已到账利息) + 利息部分
```

- 已到账超过预计时用已到账，不会因为填少了反而变少
- 其他税前收入（Contract income (B2B) 等）不变，还是只算已到账的
- 不自动推算全年（定期一次性到账，按月平均会算多好几倍）
- 预计全年利息填 0 也是"填了"，利息部分 = 已到账利息，不显示"利息只算到 MM-DD"（R14.6）
- 没填时看板写明利息只算到哪天，见 R14.6
