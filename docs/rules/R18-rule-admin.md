# R18. 规则管理（2026-10-25 新增）

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。

设置 → 规则（`/settings/rules`），能看到本家庭所有分类规则，新建、修改、删除。预置规则（`is_system = true`）和自己建的一样处理，只多一个"预置"标签。

## R18.1 列表

| 列 | 内容 |
| --- | --- |
| 关键词 | 大写 |
| 匹配方式 | 包含（`contains`）/ 开头是（`starts_with`） |
| 分类 | 分类 tag（design/README 第 3 节的颜色） |
| 命中 | 见下面 |
| 预置 | `is_system = true` 的显示小标签 |

- 默认按关键词字母排序；可以搜关键词（包含，不区分大小写）、按一级分类筛选
- **命中**：本家庭的交易如果现在重跑 R7，有几笔会用到这条规则（这条规则在 R7 第 3 步胜出）。只看 merchant，不管交易现在是什么分类、来源是什么。内部转账（`transfer_status` 为 `auto` 或 `confirmed`）和命中系统规则（R7 第 2 步）的不算
- 命中数能一眼看出关键词起得太宽（命中一大堆）或者没用（0 笔）
- 匹配方式是"包含"的，命中数能点，跳 F8 带商家筛选 = 关键词（F8 商家筛选也是包含，R16.5）。"开头是"的不能点，F8 没有开头匹配，点过去数字会对不上
- F8 里列出的笔数可能比命中数多：被更长关键词抢走的、内部转账、命中系统规则的商家名里也有这个词。命中数旁边（悬停或小字）写"F8 按商家搜索，笔数可能更多"，F8 不加"按规则筛选"（2026-10-26 补）

## R18.2 新建和修改

- 字段：关键词、匹配方式、分类。`priority` 不在界面上改，新建的是 0
- 关键词按 R13 处理：去首尾空格、多个空格合成一个、转大写，最长 100 字符，不能为空
- 分类的可选范围同 R16.3（内部转账、归档的不能选）
- `(keyword, match_type)` 在本家庭唯一。和别的规则撞了就报错"已有规则 X → Y"，不合并，让用户去改那一条。改的是自己这条且关键词没变，不算撞
- F8 弹窗存的规则仍然固定是"包含"（R16.9），只有这个页面能选"开头是"
- 修改预置规则后 `is_system` 不变，还显示"预置"标签（2026-10-26 补）

## R18.3 删除

- 删除前弹窗确认，写明命中几笔
- 删除只删规则，**不动**已经分好类的交易（它们的 `category_source` 还是 `rule`）

## R18.4 新建、修改、删除之后

和 R13 一样，问"要对 N 笔应用吗"，N 是 R7.2 的预览数。选应用就按 R7.2 重跑：

- `rule` 来源和未分类的交易整套重跑 R7。删掉的规则、改掉的关键词不再命中，又没有别的规则命中 → 变回未分类
- `manual`、多拆分的照 R7.2 不动

例子：有规则 `CAFE` → Coffee & tea，`BLUE CAFE BAR` 被它分成 Coffee & tea（`rule`）。

| 操作 | 不应用 | 应用 |
| --- | --- | --- |
| 删除 `CAFE` | 还是 Coffee & tea | 变回未分类 |
| `CAFE` 改成 `BLUE CAFE` | 还是 Coffee & tea | 还是 Coffee & tea（新关键词仍命中） |
| `CAFE` 的分类改成 Restaurants | 还是 Coffee & tea | 变成 Restaurants，归属人按 R5.1 重算 |

## R18.5 预置规则和 seed

seed 脚本**只在本家庭还没有分类时**插分类和预置规则（第一次 seed），见 R19.5。之后再跑 seed 不碰 `category_rule`，管理页里删掉或改过的预置规则不会被加回来。

以后 `seed-categories.md` 加了新的预置规则，已有的家庭要在管理页手动建。
