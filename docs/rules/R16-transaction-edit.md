# R16. 流水查询里的修改（F8，2026-10-24 新增）

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。

## R16.1 多拆分交易

一笔交易像一张小票，拆分是小票里的一部分商品（按分类 + 归属人分堆，不是每件商品一行）。

- 只有主拆分的交易：列表里一行，行内直接改分类、归属人
- 有多个拆分的交易：主行显示"已拆分 N"，**主行不能改**；下面展开成子行，每个拆分一行，各自改分类、归属人
- 拆分的金额、新增、删除只在交易详情里做（R15.2、R15.3）
- 批量修改**跳过**有多个拆分的交易，结果里提示跳过了几笔
- 批量修改的结果（2026-10-24 补）：
  - "改了"包括值本来就一样、实际没变的；"跳过"只算本节和 R16.2 跳过的
  - 选中的交易有一笔找不到（比如已经撤销导入），整批报错、一笔都不改，提示刷新
  - 一次最多 200 笔（列表一页的上限）

## R16.2 转账行

- `transfer_status` 为 `auto` 或 `confirmed` 的交易，分类**不能改**，只能改归属人
- 批量修改改分类时跳过这些交易，计入"跳过"。同时改分类和归属人时也整笔跳过，归属人也不改（2026-10-24 补）
- `suggested` 的交易分类是未分类，可以照常改；改了以后仍是 `suggested`，确认或拒绝按 R6.3

## R16.3 分类下拉的可选项

| 分类 | 能不能选 |
| --- | --- |
| 所有 expense、income 分类（一级和二级，归档的除外） | 能 |
| 系统分类：未分类、现金支出、银行费用 | 能 |
| 系统分类：内部转账 | **不能**。转账只能由 R6.1 识别、R6.2 配对或 R6.3 确认产生 |

一级分类归档后，它下面的二级也不能选，即使二级自己没归档（2026-10-24 补）。

## R16.4 手动改分类和归属人

- 改分类：`category_source = manual`，`is_pre_tax` 按新分类的默认值（R7），归属人按 R5.1 重算
- 改归属人：`member_source = manual`

## R16.5 筛选

**类型**按 R10 的分类口径，不看金额正负：

| 类型 | 条件（拆分的分类） |
| --- | --- |
| 收入 | kind = `income` |
| 支出 | kind = `expense`，加上现金支出、银行费用 |
| 内部转账 | 内部转账 |
| 未分类 | 未分类 |

所以 MEDICARE BENEFIT +45.80（Personal & medical / Other）算"支出"类型。

**合计**：

- 列表一笔交易一行，只要有一个拆分命中筛选条件就列出
- 筛选条件里有分类、归属人、类型或是否税前时，合计**只加命中的拆分**，和 R10 统计一致
- 只按交易本身的字段（时间、账户、状态、商家、金额范围）筛选时，合计就是交易金额之和
- 金额范围按**交易**金额比较，不按拆分

例子：拆分用例做完后（#19 主拆分 -35.40 Supermarket，另两个拆分 -15.00、-8.00），筛选 Groceries / Supermarket，#19 列出，合计里只算 -35.40。

## R16.6 存规则时关键词已经存在

`(keyword, match_type)` 在本家庭唯一。已经有同样的规则时：

- 指向的分类相同 → 什么都不做，直接进入"是否应用"（R7.2）
- 指向不同分类 → 对话框提示"已有规则 COLES → Groceries / Supermarket"，确认后把这条规则改成新分类（预置规则也可以改），再问是否应用

## R16.7 R6.2 只配对不改的交易

R6.2 里另一半分类是 `manual`、只配对没改的交易（有 `transfer_pair_id`，`transfer_status = none`），列表里显示小标签"已配对，分类是手动的"，不做单独筛选。

## R16.8 可能重复的 pending

R8.2 候选 ≥ 2 时写进 `import_batch.warnings` 的可能重复，在 F8 里提示放到 **M6** 做（M6 之前录不进 pending）。具体怎么判断见 R17.6。

## R16.9 什么时候弹"存成规则"（2026-10-24 补）

改完分类后，下面三条都满足才弹 R13 的"存成规则"对话框：

- 分类真的变了（选了原来的分类不弹）
- 新分类是 expense 或 income。改成未分类、现金支出、银行费用不弹
- 改的是主拆分。多拆分交易的子行不弹，因为规则按整笔交易的商家匹配
- 有类似交易：本家庭**除了这笔以外**，还有交易的 merchant 包含建议的关键词（R13，不区分大小写，不管它现在是什么分类）（2026-10-25 补）

前三条满足、第四条不满足时（这个商家目前只有这一笔），不弹对话框，改分类的 toast 里带一个"存成规则"按钮，点了打开同一个对话框。规则主要是给以后导入用的，所以入口留着，只是不打断。

例子（joint）：把 #14 MELB ASIAN MARKET 改成 Groceries / Asian grocer → #13 也含 `MELB ASIAN MARKET`，弹。把 #15 UNKNOWN SHOP PTY LTD MELBOURNE 改成 Shopping → 只有它自己，不弹，toast 里有"存成规则"。

从这个对话框存的规则，匹配方式固定是 `contains`，对话框里不让选。


## R16.10 改归属人后同商家一起改（2026-10-25）

在 F8 列表里改了一笔交易主拆分的归属人后（行内改，不含批量修改和详情页的拆分），看有没有同商家的交易要一起改：

- 范围：本家庭除了这笔以外，merchant 包含这笔建议关键词（R13 的 `suggestKeyword`，不区分大小写）的交易
- 只算：只有主拆分、归属人不是新选的人、`member_source` 不是 `manual`（用户以前手动定过的不动）、`transfer_status` 不是 `auto` 或 `confirmed`
- 有 ≥ 1 笔 → 弹窗"商家含 X 的还有 N 笔归属人不是 Y，要一起改吗？"，确认后这些都改成 Y，`member_source = manual`，一个事务
- 0 笔不弹
- 只改已有的。以后导入的同商家交易还是按 R5 算，要长期生效就改分类的默认归属人（R19）
- 同一次操作里分类也改了时，先走 R16.9 存规则，再问这个

例子（joint）：#4 GONG CHA 改成 Female → #5 也含这个商家、是 Male（card）→ 弹窗 N = 1，确认后 #5 变成 Female（manual）。
