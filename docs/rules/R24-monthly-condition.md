# R24. 每月条件（F13，2026-11-04 新增，M10）

> 业务规则的一部分，总则和索引见 [`docs/business-rules.md`](../business-rules.md)。其他规则按编号去 `docs/rules/` 找。
> 用例见 [`fixtures/cases/15-monthly-conditions.md`](../../fixtures/cases/15-monthly-conditions.md)。

每个账户可以配置每月条件（bonus interest、免月费），app 按当月流水判断"已满足 / 还差多少 / 已经失败"。用户自己按银行的说明录，app 不内置哪家银行是什么条件。

- 条件只看 `transaction.amount_cents`、日期、账户、状态、`transfer_status`、对方账户，**不改任何交易的分类、转账状态**。唯一用到拆分分类的是"月费"（系统分类 `bank_fee`，显示名 Bank fees）和"利息"（`Income / Interest`）
- 看板、F8、预算、税务、月均、余额（R23）的数字都不变
- 判断结果**每次实时算，不存**（和 R23.3 差额一样）。补导了流水、改了分类，结果自己变。只有"其他"类型的手动勾选要存（R24.7）
- 月份按 Melbourne 自然月：`[startOfMonth, endOfMonth]`，日期是 `YYYY-MM-DD` 字符串
- "今天"按 Melbourne。纯函数把今天当参数传进来，不自己取

## R24.1 条件和配置

**类型**

| 类型 key | 显示 | 参数 | 看哪个账户 |
| --- | --- | --- | --- |
| `min_deposit` | 当月存入至少 $X | 金额（分，> 0）、哪些存入算数（R24.3） | 本账户 |
| `no_withdrawal` | 当月不取款 | — | 本账户 |
| `balance_growth` | 月末余额比上月末高 | — | 本账户 |
| `linked_min_deposit` | 关联账户当月存入至少 $X | 金额（分，> 0）、哪些存入算数 | 本账户的 `linked_account_id` |
| `linked_card_count` | 关联账户当月刷卡至少 N 笔 | 笔数（整数，≥ 1） | 本账户的 `linked_account_id` |
| `other` | 其他（文字描述） | 文字，不能为空 | — app 判断不了，每月手动勾（R24.7） |

下面说"看的账户"，指这一列的账户。

**结果**：每个条件有自己的结果，`bonus`（拿 bonus）或 `fee_waiver`（免月费）。

- 一个账户可以有多个条件
- 同一个账户、同一个结果有多个条件时，**全部满足才算拿到**，有一个失败就没拿到。不同结果分开算（R24.5 的合并）
- 不做"任一满足"。以后真遇到二选一的条件，再在条件上加"全部 / 任一"

**生效月份**：

- `effective_from`：从哪个月开始判断（存月初日期）。添加时默认本月，可以选更早的月份补看历史，**不能晚于本月**
- `disabled_from`：从哪个月起不判断（存月初日期），`null` = 还在用
- 这个条件判断的月份 = `effective_from ≤ 月份 < disabled_from`（`disabled_from` 是 `null` 时没有上限）

**添加 / 修改 / 删除**（界面上这三个，后台没有真删）：

- 添加：建一条，`effective_from` 按上面
- 修改：旧的 `disabled_from = 本月`；建一条新的，参数是改过的，`effective_from = 本月`。以前的月份还按旧参数算，不按新参数重算
- 删除：`disabled_from = 本月`
- 所以停用以后**本月就不判断、不显示**，历史里停用以前的月份照样显示
- 本月添加、本月又改或删的那条：`effective_from = disabled_from`，一个月也不判断，历史里也没有它
- 设置页只列在用的条件（`disabled_from` 是 `null`）

**校验**（保存时，按顺序，第一条不过就报错、不保存）：

| # | 情况 | 错误 |
| --- | --- | --- |
| 1 | 账户不存在或不是本家庭的 | 找不到这个账户 |
| 2 | 账户已归档 | 归档的账户不能加条件 |
| 3 | 关联类型，账户的 `linked_account_id` 是 `null` | 这个账户还没有设置关联账户 |
| 4 | 金额类型，金额不是正整数分 | 金额要大于 $0 |
| 5 | `linked_card_count`，笔数不是 ≥ 1 的整数 | 笔数至少 1 笔 |
| 6 | `other`，文字去掉首尾空格后是空的 | 写一下条件是什么 |
| 7 | `effective_from` 晚于本月 | 生效月份不能晚于本月 |

- 现金账户、`bank = other` 的账户也能配，不限制。现金账户不能关联（R23.4 #4），所以只能配本账户类型
- 修改、删除时也校验 #1（条件属于本家庭）

**已经配好的条件后来情况变了**：

- 关联类型配好以后关联被删掉（`linked_account_id` 改成 `null`）→ 这个条件状态是 `unknown`，显示"关联账户没设置"，不判断。关联改成了别的账户 → 按**现在**的关联账户算，历史月份也一样
- 关联账户后来归档了 → 照样判断，显示"{名字}（已归档）"
- 本账户归档了 → 它的条件都不判断、不显示、不提示

## R24.2 存入、取款、刷卡笔数

只看**看的账户**、**当月**、**`status = confirmed`** 的交易（银行按入账算）。pending 不算，"还差多少"里也不提 pending。

先算每笔交易的**有效金额**：

```
有效金额 = amount_cents − Σ 这笔交易上分类是 Bank fees 或 Income / Interest 的拆分金额
```

拆分的符号和交易一致（R15），所以正数交易减完还是 ≥ 0，负数交易减完还是 ≤ 0。

| 口径 | 哪些交易 | 金额 |
| --- | --- | --- |
| **存入** | 有效金额 > 0 | 有效金额 |
| **取款** | 有效金额 < 0 | 有效金额的绝对值 |
| **刷卡** | 是取款，而且 `transfer_status = none` | 每笔算 1 笔，不看金额 |

- 存入**不看 `transfer_status`**：从自己别的账户转进来也算（ANZ → ANZ 也算，M10-0 确认）。工资、退款也算（退款是正数）
- 利息、月费退回不算存入：ANZ 的 `REVERSAL OF ACCOUNT SERVICING FEE ...` 是正数，R7 分到了 Bank fees，不能算进 $2000
- 取款**不看 `transfer_status`**：转到自己别的账户也算取款（saver 条件一般就是这个意思）
- 月费（Bank fees）、利息冲正（Income / Interest 的负数）不算取款，也不算刷卡
- 刷卡：内部转账（`auto`、`confirmed`）和还没确认的转账建议（`suggested`）都不算。银行一般只算刷卡（POS / 网购），描述里分不清 BPAY、ATM，这些先接受多算
- 一笔交易拆了一部分到 Bank fees 或 Interest：只去掉那一部分，剩下的照样算

## R24.3 哪些存入算数、对方账户

`min_deposit`、`linked_min_deposit` 的参数：

| 值 | 显示 | 意思 |
| --- | --- | --- |
| `any` | 任何存入 | R24.2 的存入全部算 |
| `exclude_linked` | 不算关联 saver 转回来的 | 去掉对方账户是"关联到看的账户的账户"的存入，即对方账户的 `linked_account_id` = 看的账户 |

- 不做"排除同一家银行的账户"：ANZ 自己账户之间转账算存入（M10-0 确认），这个选项当初只为这个不确定才加
- `linked_min_deposit` 用 `exclude_linked` 时，"关联到看的账户的账户"一般就包括配条件的这个 saver 自己
- 关联关系按**现在**的 `linked_account_id` 算，历史月份也一样

**对方账户**（只有 `exclude_linked` 要用），按顺序：

1. 有 `transfer_pair_id` → 配对那笔交易的账户（R6.2）
2. 没配对、`transfer_status` 是 `auto` 或 `confirmed` → `storedTransferAccountId`（从脱敏描述重跑 R6.1，`src/lib/rules/transfer.ts`）；它返回 `null` 时算未知
3. 别的（`none`、`suggested`；PayID 只有人名、外行转账认不出、R6.3 还没确认的建议）→ **未知**

- **对方未知的存入按"算数"处理**。这样不会因为认不出把条件误判成没满足
- 进度旁边小字"N 笔存入认不出来自哪个账户，按算数处理"：N = 这个月对方未知的存入笔数，工资、退款也算进 N。N 是 0 不显示；只有 `exclude_linked` 的条件显示这行

## R24.4 月末余额

在 `src/lib/rules/balance.ts` 加 `balanceAt(anchors, transactions, date)`：`date` 这一天**结束时**的入账余额。

```
锚点 (A, D) = 日期 ≤ date 的锚点里，按 R23.1 的顺序选出的那个
balanceAt  = A + Σ amount_cents（status = confirmed，D < 交易日期 ≤ date）
没有日期 ≤ date 的锚点 → null
```

- 锚点来源、选法和 R23.1 一样（PDF 批次 + 手动）。只看 confirmed，和 R23.3 校准一样
- `date` 当天的交易算进去（`date` 这一天结束时）；锚点当天的不算（已经在锚点里）
- 比 `date` 晚的锚点不用

`balance_growth`（看本账户）：

```
上月末 = balanceAt(上个月最后一天)
本月末 = balanceAt(这个月最后一天)        月份过完了
现在   = balanceAt(今天)                 月份没过完
```

- 上月末是 `null` → `unknown`，显示"没有余额，判断不了"，不算失败（有上月末就一定有现在、本月末）
- 月份没过完：`in_progress`，显示"现在比上月末多 / 少 $X"，一样时显示"现在和上月末一样"
- 月份过完：本月末 **>** 上月末 → `met`；**≤** → `failed`（一样也算没满足）

## R24.5 状态

每个条件每个月一个状态：

| 状态 | 意思 |
| --- | --- |
| `met` | 已满足 |
| `failed` | 已经失败 |
| `in_progress` | 本月还没过完、还没满足，也还没失败 |
| `unknown` | 判断不了：没余额、关联账户没设置、"其他"还没勾 |

**月份过完** = 今天（Melbourne）**晚于**这个月最后一天，不管数据导到哪天。

| 类型 | 月份没过完 | 月份过完 |
| --- | --- | --- |
| `min_deposit`、`linked_min_deposit` | 存入合计 ≥ X → `met`；否则 `in_progress`，还差 X − 合计 | ≥ X → `met`；否则 `failed` |
| `linked_card_count` | 笔数 ≥ N → `met`；否则 `in_progress`，还差 N − 笔数 | ≥ N → `met`；否则 `failed` |
| `no_withdrawal` | 有取款 → `failed`；否则 `in_progress`（"到目前没有取款"） | 有取款 → `failed`；否则 `met` |
| `balance_growth` | 见 R24.4 | 见 R24.4 |
| `other` | 见 R24.7 | 见 R24.7 |

- 关联类型没有关联账户 → `unknown`，排在所有判断前面
- 存入够了、笔数够了月中就是 `met`，不等月底
- `no_withdrawal`、`balance_growth` 月中不会是 `met`，月份过完才定
- `no_withdrawal` 失败原因写**日期最早**的那笔取款（同一天按 `created_at`）：对方账户认得出 → "12-03 转出 $200.00 到 CBA Female"；认不出 → "12-03 取出 $200.00（{merchant}）"。这个月不止一笔时后面加"，本月共 N 笔取款"
- 月份过完、看的账户"数据截至"（R24.6）早于这个月最后一天 → `met`、`failed` 的说明后面加"（数据截至 MM-DD，可能不准）"。`unknown` 不加
- ANZ 说"当月最后一个工作日前存入"。不管工作日，按自然月；月底那几天存的钱算不算以银行收没收月费为准（R24.8）

**显示文字**（金额用 `formatAud`）：

| 类型 | `in_progress` | `met` | `failed` |
| --- | --- | --- | --- |
| 存入类 | 存入 $合计 / $X，还差 $差额 | 存入 $合计 / $X | 存入 $合计 / $X，还差 $差额 |
| `linked_card_count` | 刷卡 n / N 笔，还差 k 笔 | 刷卡 n / N 笔 | 刷卡 n / N 笔，还差 k 笔 |
| `no_withdrawal` | 到目前没有取款 | 没有取款 | 取款原因（见上） |
| `balance_growth` | 现在 $余额，比上月末多 / 少 $X（或"和上月末一样"） | 月末 $余额，比上月末多 $X | 月末 $余额，比上月末少 $X（或"和上月末一样"） |

关联类型前面加"{关联账户名}："。

**合并**（同一个账户、同一个月）：

- 按结果合并（同一个 `bonus` 或同一个 `fee_waiver` 的条件）：
  1. 有 `failed` → 没拿到
  2. 全部 `met` → 拿到
  3. 有 `in_progress` → 进行中
  4. 其他 → 判断不了
- 历史的小格（R24.10）：这个账户这个月**所有**条件（不分结果）用同样的顺序合并，显示 失败 / 满足 / 进行中 / 判断不了
- 只合并这个月在判断的条件（R24.1 生效月份）

## R24.6 数据截至哪天

每个账户：

```
截至 = max(R23.1 选出的当前锚点日期, 这个账户最晚一笔 confirmed 交易的日期)
```

- 和 R23.2 的"截至"取法一样，但**不算 pending**
- 锚点、confirmed 交易都没有 → 没有截至日期，显示"还没有数据"；月份过完时后缀写"（还没有数据，可能不准）"
- 关联类型看**关联账户**的截至日期；其他类型看本账户
- 显示格式 `MM-DD`。进度、首页提示、历史都写"数据截至 MM-DD"

## R24.7 "其他"类型

- 每个月一个手动勾：满足了 / 没满足 / 还没勾。存 `(condition_id, month)`
- 满足了 → `met`；没满足 → `failed`；还没勾 → `unknown`（显示"还没勾"），月份过完也一样
- 可以改，可以清掉（清掉 = 删那一行，回到还没勾）
- 只能勾这个条件在判断的月份（R24.1），不能勾未来的月份
- 在 `/accounts` 勾，不在设置页
- 首页提示不管"其他"（R24.9）
- 文字、勾选不进 R24.2 的计算，只当状态用

## R24.8 月费校验

prd F13 "已满足的月份流水里还是出现了月费"。

- 只看 `fee_waiver`：某个账户某个月，`fee_waiver` 合并结果是**拿到**（R24.5，全部 `met`）
- 这个账户这个月（`[月初, 月末]`）confirmed 交易上 Bank fees 拆分的**净额** < 0 → 提示"这个月判断满足了，但还是收了 $X 月费，条件配置可能不对"（$X 是净额的绝对值）
- 为什么看净额：ANZ 满足了也会先扣 $5（`ACCOUNT SERVICING FEE`），再退回 $5（`REVERSAL OF ACCOUNT SERVICING FEE MINIMUM $2000 IN DEPOSITS RECEIVED`），两笔都在流水里（M10-0 确认）。扣了又退的净额是 0，不提示
- ANZ 月费在**当月最后一个工作日**扣（碰上非工作日提前，不跨月），退回也在同月。所以只看同一个月；下个月 1 号出现的月费算下个月
- 只看 Bank fees 分类，金额不限（别的手续费也会被提示，先接受）
- 本月也校验：月中已经 `met`、又出现了月费，也提示
- "没满足但没收月费"不提示（可能银行宽限，也可能是 app 判断错）
- `bonus` 不做校验（bonus 利息和基础利息在流水里分不开）

## R24.9 首页提示

prd 第 6 节原则 1：首页只回答"钱花哪去了"，所以只放一行。

- 只在本月**最后 5 天**（含最后一天）出现：今天 ≥ 本月最后一天 − 4。天数写成常量 `CONDITION_REMINDER_DAYS = 5`
- 算哪些条件：本家庭、没归档的账户、本月在判断的、状态是 `in_progress` 的，而且是下面这几种（有"还差"的）：
  - `min_deposit`、`linked_min_deposit`、`linked_card_count`
  - `balance_growth`：现在 ≤ 上月末时
- 不算：`no_withdrawal`（"到目前没有取款"不用提醒）、`balance_growth` 现在已经比上月末高的、`other`、`unknown`、`met`、`failed`（已经来不及了，在 `/accounts` 看）
- 一个条件都没有 → 不出现
- **一个** → 一行说这个条件：

| 类型 | 文字 |
| --- | --- |
| `min_deposit` | {账户} 本月存入还差 $X（数据截至 MM-DD） |
| `linked_min_deposit` | {账户} 的关联账户 {关联账户} 本月存入还差 $X（数据截至 MM-DD） |
| `linked_card_count` | {账户} 的关联账户 {关联账户} 本月刷卡还差 N 笔（数据截至 MM-DD） |
| `balance_growth` | {账户} 现在比上月末少 $X（数据截至 MM-DD）；一样时"{账户} 现在和上月末一样，月底要比上月末高（数据截至 MM-DD）" |

- **多个** → "N 个账户条件本月还没满足（数据截至 MM-DD）"，N 是条件个数（不是账户个数），日期取这些条件里**最早**的截至日期
- 截至日期按 R24.6（关联类型看关联账户）；没有截至日期的写"还没有数据"
- 点了跳 `/accounts`
- 不放条件卡片，不跟看板的时间段和归属人筛选

## R24.10 `/accounts` 和历史

- 有条件（本月在判断的）的账户卡片下面加"本月条件"：每个条件一行，类型说明（R24.1 的显示 + 参数 + 结果"bonus / 免月费"）+ 状态 + R24.5 的显示文字 + "数据截至 MM-DD"
  - `exclude_linked` 的加 R24.3 的小字
  - `other` 的一行上能勾满足了 / 没满足 / 清掉
  - 本月有 R24.8 提示的，也显示在这里
- **历史**：最近 12 个月（含本月），每月一个小格（R24.5 的账户合并：失败 / 满足 / 进行中 / 判断不了）
  - 从这个账户所有条件里最早的 `effective_from` 开始，更早的月份不显示
  - 中间某个月一个在判断的条件都没有 → 空格子，写"没有条件"
  - 有 R24.8 提示的月份标出来
  - 点开看那个月：每个条件的状态和显示文字、按结果合并的结论（"bonus：拿到"、"免月费：没拿到"）、R24.8 提示、那个月的利息
- **每月利息**：这个账户那个月的 `Income / Interest` 拆分合计，算法同 R23.6（冲正冲减、pending 也算），只是范围换成 `[月初, 月末]`。没有显示 $0.00
- 配置在 `/settings/accounts` 的账户编辑里（M9 定的：设置页只管配置）。`/accounts` 只显示进度和勾"其他"

## R24.11 不做

- 内置银行条件模板
- 自动推荐"这个月取钱还是下个月取"
- 固定周期转账自动确认（N2.5 提过，开始前再定）
- 按工作日算月底
- bonus 利息的预估金额
- "任一满足"（R24.1）
- 按刷卡方式（POS / BPAY / ATM）细分刷卡笔数
